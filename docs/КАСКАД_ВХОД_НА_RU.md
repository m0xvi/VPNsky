# Каскад v2: русский VPS как вход-узел (без DNAT)

Дата: 6 ноября 2026. Это **замена** схемы с прозрачным DNAT (`nsky-relay.sh`).
Старая схема доводила ClientHello телефона до нидерландской ноды, но трафик
обратно не шёл: «ПОДКЛЮЧЕН», 0 байт. Причина так и не была установлена.

Здесь другой принцип: русский VPS **не пересылает чужие пакеты**, а сам
принимает TLS телефона и отдельным исходящим соединением идёт на NL-ноду.

```
телефон (LTE) ──VLESS+REALITY──▶ русский VPS (Xray) ──VLESS+REALITY──▶ NL-нода ──▶ интернет
               один TLS к близкому IP          обычный маршрут датацентров
```

| Было (DNAT) | Стало (вход-узел) |
|---|---|
| пакет телефона прозрачно пролетает 2 хопа | TLS телефона завершается на RU |
| PMTU/MSS, conntrack, «полуоткрытые» сессии между ДЦ | два независимых TCP-соединения |
| телефон видит зарубежную ноду через NAT | телефон видит один REALITY-хост на российском IP |
| подписка тянется с зарубежного домена → таймаут на LTE | ссылка добавляется вручную, подписка не нужна |
| проверить можно только с телефона | цепочка RU→NL проверяется **без телефона** |

NL-сервер, панель Remnawave, подписки и ключи существующих инбаундов
**не изменяются**. Всё, что делает скрипт, живёт в `/opt/nsky-entry` и
снимается одной командой.

---

## Что нужно от вас: одна ссылка и одна команда

### Шаг 1. Взять ссылку на прямой хост (без пометки «(RU)»)

Любой из вариантов:

- **В Happ:** открыть список серверов → долгое нажатие (или «⋮») на
  **`NSky REALITY`** (без `(RU)`) → «Поделиться» / «Share» / «Копировать ссылку».
  Скопировалась строка, начинающаяся с `vless://`.
- **В панели:** Users → ваш пользователь → иконка ссылки →
  Subscription links → скопировать строку `vless://…` для хоста без `(RU)`.

Это ссылка на **прямой** хост. Внутри неё уже есть адрес и порт NL-ноды,
UUID пользователя, `pbk`, `sid` и SNI — вводить их руками не нужно,
и в чат их присылать не надо.

### Шаг 2. На русском VPS — две строки

Скачать скрипт (подставьте ссылку из раздела «Скачивание» в конце документа)
и запустить, вставив свою ссылку **в одинарных кавычках**:

```
cd /root
curl -fsSL -o nsky-entry.sh https://raw.githubusercontent.com/m0xvi/VPNsky/785aa15a4e800d5a5454cc11477c0049ce734768/deploy/nsky-entry.sh
```

```
bash nsky-entry.sh 'vless://...'
```

> Вставляйте по одной строке, Enter после каждой. Если PuTTY склеил строки —
> `Ctrl+C` и повторите.
>
> Ссылку в кавычках можно вставить и после запуска: скрипт ничего не спросит,
> он либо сделает, либо скажет, что именно не так.

Скрипт сам: поставит Xray (если его нет), сгенерирует **свою** пару ключей
REALITY для входа, займёт `443/tcp` (+ `8443/tcp` как резерв), снимает
мешающие остатки DNAT, открывает порты в `ufw`, ставит systemd-службу
`nsky-entry` и **сразу проверяет всю цепочку**.

### Шаг 3. Прочитать итог самопроверки

В конце будет блок «Самопроверка». Нужны две зелёные строки:

```
✓ прямой выход с VPS: <IP русского VPS>
✓ через каскад выходной IP <IP NL-ноды> — это NL-нода. Каскад РАБОТАЕТ
```

Это **доказательство без телефона**: Xray на русском VPS сам сходил в интернет
через NL-ноду и показал её внешний IP. Если эти строки зелёные — серверная
часть каскада работает end-to-end, чего старая диагностика так и не доказала.

Ниже скрипт печатает **ссылку для Happ**:

```
vless://…@<IP_русского_VPS>:443?…&pbk=…&sid=…#NSky-RU-REALITY-443
```

### Шаг 4. Телефон

1. **На Wi-Fi:** Happ → «+» → «Добавить из буфера обмена» (вставить ссылку
   из шага 3). Появится узел `NSky-RU-REALITY-443`.
2. Выключить Wi-Fi, включить мобильный интернет.
3. Выбрать `NSky-RU-REALITY-443` → «Подключить» → открыть `2ip.ru`.
   Должен показаться **нидерландский** IP.

Если на LTE не пошло — попробовать резервную ссылку `NSky-RU-REALITY-8443`
(тот же сервер, другой порт; печатается там же).

## Если что-то не так

| Симптом | Что значит | Что делать |
|---|---|---|
| `✗ через каскад трафик не прошёл` | RU не может достучаться до NL-ноды | строка выше подскажет, открыт ли TCP до NL; проверьте `ufw` на NL и что нода жива |
| `✗ REALITY не отвечает локально` | не поднялся вход | `journalctl -u nsky-entry -n 40 --no-pager` |
| `Порт 443/tcp занят другим процессом` | на RU уже что-то слушает 443 | `ss -lntp \| grep :443`; освободить или запустить с `--port 2053` |
| `Не удалось скачать Xray` | с VPS нет доступа к github.com | повторить позже или поставить Xray вручную и запустить снова |
| Всё зелёное, а с телефона не идёт | оператор режет первый хоп | попробовать `--port 8443`, затем `--sni` с российским доменом (см. ниже) |

Сменить маску REALITY (если оператор придирается к иностранному SNI на
российском IP):

```
bash nsky-entry.sh --sni www.sberbank.ru 'vless://...'
```

или коротко, без ссылки (она уже сохранена):

```
bash nsky-entry.sh --sni www.rbc.ru
```

Что прислать, если не заработало: **только вывод** `bash nsky-entry.sh --check`
(без ссылок и IP он не содержит секретов, кроме адреса вашего VPS).

## Проверка в любой момент

```
bash nsky-entry.sh --check     # служба, порты, маска, цепочка RU→NL→интернет
bash nsky-entry.sh --status    # коротко: служба, порты, куда туннель
bash nsky-entry.sh --link      # заново напечатать ссылки для Happ
bash nsky-entry.sh --remove    # снять вход-узел (NL не трогается)
```

Повторный запуск `bash nsky-entry.sh` (без ссылки) безопасен: ключи, UUID и
ссылка не меняются, конфиг перегенерируется из сохранённой ссылки.

## Что стало с прежним релеем

- DNAT-правила на `443` и `8443`, если они были, скрипт **снимает**: они
  перехватывают пакеты до локального Xray.
- Сам `nsky-relay.sh` и его правила для `2053/tcp` и `443/udp` остаются, если
  их не снимали: они больше не нужны, но и не мешают. Снять целиком:
  `bash /root/nsky-relay.sh --remove`.
- Хосты с пометкой `(RU)` в подписке после этого **не работают** — они
  указывают на DNAT-релей. Пользуйтесь ссылкой из шага 3 либо удалите
  каскадные хосты в панели (`--cascade-remove`).

## Дальше (когда заработает): 50 сотрудников

Сейчас вход-узел — отдельный Xray со своим пользователем. Для раздачи
сотрудникам есть два пути:

1. **Быстро:** одна ссылка на всех (тот же UUID) — годится для пилота, но
   нет индивидуального отзыва и учёта трафика.
2. **Правильно:** поставить на русский VPS **ноду Remnawave** и описать её
   конфиг с исходящим на NL. Тогда вход становится обычной нодой панели:
   пользователи, лимиты, отзыв и статистика — как у остальных, а в подписке
   появляется сервер с российским адресом.

Второй путь — отдельная задача; скрипт выше её не блокирует и не мешает ей.
