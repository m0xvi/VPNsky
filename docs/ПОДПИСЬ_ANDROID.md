# Подпись Android-приложения — простыми словами

## Зачем это вообще нужно

Android не даёт устанавливать приложение, которое ничем не «подписано». Подпись — это
не про платный сертификат и не про бумаги: это обычный файл-ключ, который создаётся
за две минуты и бесплатно. Он нужен, чтобы:

1. телефон согласился поставить APK;
2. **новая версия могла обновиться поверх старой.** Если подписывать разными ключами,
   Android откажется обновлять: придётся удалять приложение и ставить заново, теряя настройки.

Всё. Никаких аккаунтов, регистраций и оплаты.

## Что будет, если ничего не настраивать

Сборка пройдёт, но автоматически подпишется отладочным ключом. Тогда:

- пакет называется `ru.vpnsky.client.dev` (с точкой `.dev` на конце);
- он **не заменит** нормально установленное приложение, а встанет рядом;
- для первой проверки «а вообще запускается?» — годится;
- для раздачи сотрудникам — нет.

## Ключ нужно создать один раз

Делается на любом компьютере с Java (она есть почти везде, где стоит Android Studio).
Ключ создаётся **у вас**, никуда не передаётся и в песочницу не попадает.

### Шаг 1. Создать файл ключа

Откройте терминал (на Windows — PowerShell) в любой папке и выполните одной строкой:

```
keytool -genkeypair -v -keystore vpnsky.jks -keyalg RSA -keysize 2048 -validity 10000 -alias vpnsky -storetype JKS
```

Что произойдёт: программа задаст несколько вопросов и попросит два пароля.

- **Пароль хранилища** (`storePassword`) — придумайте и запишите.
- **Пароль ключа** (`keyPassword`) — можно тот же самый, так проще.
- Имя, организация, город — можно отвечать что угодно или нажимать Enter.
- Последний вопрос «correct?» — ответьте `yes`.

В папке появится файл `vpnsky.jks`. Это и есть ваш ключ.

> **Важно:** если потеряете этот файл или пароли, обновить приложение у сотрудников
> без переустановки уже не получится. Сохраните его в надёжном месте (например, в
> менеджере паролей или в защищённой папке), а не только на рабочем столе.

### Шаг 2. Превратить ключ в текст

GitHub не умеет хранить файлы в секретах — только текст. Поэтому файл кодируется в base64.

**Linux / macOS:**
```
base64 -w 0 vpnsky.jks > vpnsky.jks.txt
```
(на macOS, если `-w 0` не поддерживается: `base64 -i vpnsky.jks -o vpnsky.jks.txt`)

**Windows PowerShell:**
```
[Convert]::ToBase64String([IO.File]::ReadAllBytes("vpnsky.jks")) | Set-Content vpnsky.jks.txt
```

Получится один длинный текст в файле `vpnsky.jks.txt`. Его можно открыть блокнотом
и скопировать целиком.

### Шаг 3. Положить четыре значения в GitHub

Откройте: `https://github.com/m0xvi/VPNsky/settings/secrets/actions`
(в репозитории: **Settings → Secrets and variables → Actions → New repository secret**).

Создайте ровно четыре секрета — имя должно совпадать буква в букву:

| Имя секрета | Что вписать |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | всё содержимое `vpnsky.jks.txt` (одна длинная строка) |
| `ANDROID_STORE_PASSWORD` | пароль хранилища из шага 1 |
| `ANDROID_KEY_ALIAS` | `vpnsky` |
| `ANDROID_KEY_PASSWORD` | пароль ключа из шага 1 |

Всё. Больше ничего настраивать не нужно.

### Шаг 4. Собрать

Actions → **build-client** → **Run workflow**. Через 20–40 минут в разделе Actions
появится архив с APK и установщиком для Windows.

Проверить, что подпись применилась: в логе шага «Prepare signing» будет строка
`SIGNED=true`, а имя APK будет без `.dev`.

## Частые вопросы

**Это безопасно?** Ключ хранится в секретах GitHub, в логи не выводится. Секреты
доступны только тем, у кого есть права на репозиторий. Для публичного репозитория это
означает: секреты не видны никому со стороны, но любой, кто получит права на запись,
теоретически сможет их прочитать. Если это критично — держите репозиторий под контролем
доступа или перейдите на приватный с отдельной настройкой Actions.

**Что если я не хочу с этим возиться сейчас?** Тогда соберётся `.dev`-версия —
поставить и посмотреть, как всё работает, хватит. Настроить подпись можно в любой момент
до раздачи сотрудникам.

**Можно ли потом сменить ключ?** Можно, но тогда всем придётся удалить приложение и
поставить заново. Лучше сразу сделать нормальный ключ и его не терять.

**Где это отражено в коде?** `app/android/app/build.gradle.kts`, строки 16–22 и 43–50:
если файл `keystore.jks` и пароли на месте — подписывается вашим ключом, иначе отладочным.
