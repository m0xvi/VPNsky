# Записка следующему агенту — NSky (репозиторий VPNsky)

Дата передачи: 2026-11-06. Ветка: `arena/998588fa-vpnsky`, PR открыт.
Общаться с пользователем по-русски. Команды для PuTTY — короткими блоками,
без разметки, по одной строке на команду.

Записка лежит в публичном репозитории, поэтому **инфраструктурные
идентификаторы (домен, IP, пароли, секреты, ссылки) сюда сознательно не
включены** — они в истории сессии и на серверах в
`/opt/nsky/install-state.env` (chmod 600). Не выносить их ни в этот файл,
ни в логи, ни в чат.

---

## 1. Что за проект

NSky — корпоративный VPN для 50+ сотрудников. Гибрид из открытого кода:

- **Сервер**: панель Remnawave (Docker: remnawave + Postgres + Valkey),
  Caddy (HTTPS, подписка), Xray-нода (`remnawave/node:3.4.4`, Xray
  v26.10.31). Своего control plane не пишем — только готовые решения и
  скрипт-обвязка.
- **Клиент**: форк FlClash (Flutter), ребренчинг в NSky. Упоминаний
  FlClash в продукте быть не должно (код-ссылки `fl_clash` в пакете —
  допустимы, видимые строки и названия — нет).
- Exit-нода — Нидерланды. Каскад через русский VPS для мобильных сетей РФ.
- Порядок платформ: Windows → Android → iOS. Оба режима туннеля
  (сплит/весь трафик). Один GUI на все платформы, админ-режим обязателен
  на всех платформах, включая iOS.
- «2 админа» невозможно технически: seed панели удаляет всех админов,
  кроме старейшего (`prisma/seed/seeders/12_verify-admin.ts`). Замена:
  1 админ + API-токен для второго человека.

## 2. Архитектура сервера (как есть сейчас, всё проверено живым прогоном)

Порты: `22` SSH, `80` ACME, `443/tcp` — только подписка под секретным
сегментом (`/<SUB_SECRET>/api/sub/...`, сам `/api/sub` отдаёт 404 силами
Caddy), `8443/tcp` REALITY (маскировка www.microsoft.com), `2053/tcp`
XHTTP, `443/udp` Hysteria2, `8444/tcp` панель — **только с IP офиса**
(ufw), `2222/tcp` нода — **только из docker-сети** (ufw allow from
172.18.0.0/16, автопроверка с откатом в установщике, шаг 9.9).

Установщик `deploy/nsky-install.sh` (версия **2026-11-06.6**): один скрипт,
идемпотентен, `<домен> <email>` + флаги `--wipe`, `--check`,
`--panel-ip <IP,...>`, `--panel-port`, `--cascade <IP>`, `--cascade-remove`.
Состояние — `/opt/nsky/install-state.env` (SERVER_IP, DOMAIN, DB_PASS,
APP_SECRET, METRICS_PASS, ADMIN_USER, ADMIN_PASS, API_TOKEN, PROFILE_UUID,
SQUAD_UUID, NODE_UUID, NODE_SECRET, TEST_SHORT_UUID, SUB_URL, SUB_SECRET,
CASCADE_IP, PANEL_PORT, PANEL_ALLOW_FROM). Перед изменениями делает снимок
в `/opt/nsky/backups/`.

Релей `deploy/nsky-relay.sh` (русский VPS): чистый DNAT
(8443/tcp, 2053/tcp, 443/udp → NL) + MASQUERADE + форвард + TCPMSS clamp.
Без слушающих сервисов — сканеру нечего ловить, домен не нужен.
Идемпотентен, `--status` / `--remove`, автозапуск через systemd
(`nsky-relay.service`), файл состояния `/opt/nsky-relay/nl-ip`.

Каскад в подписке: хосты с суффиксом « (RU)» на **тех же инбаундах** —
сквад ссылается только на инбаунды (проверено по `InternalSquadSchema`),
поэтому они попадают в ту же подписку автоматически. Итого 6 ссылок
(3 прямых + 3 через релей).

## 5. Ключевые проверенные факты (не переоткрывать)

- **ufw применяет правила сверху вниз, первое совпадение выигрывает.**
  Общий `ufw deny <порт>` перед `allow from <IP>` БЛОКИРУЕТ разрешённый IP.
  Не добавлять общий deny для порта панели никогда; закрытость даёт
  `ufw default deny incoming`.
- У Remnawave нет настройки IP-allowlist ни в UI, ни в env — ограничение
  только снаружи (ufw или reverse-proxy).
- Панель рвёт соединения без заголовков `x-forwarded-for: 127.0.0.1` и
  `x-forwarded-proto: https` (proxy-check middleware) — установочный
  `api()` их уже шлёт.
- Подписка для «неизвестных» User-Agent отдаётся в **base64** — проверочная
  логика должна декодировать (в установщике уже так).
- Caddy по умолчанию слушает h3 (UDP 443) — глобальный блок
  `servers { protocols h1 h2 }` обязателен, иначе падает Xray/Hysteria2.
- `alpn: ""` → Validation failed (enum); пустые sni/alpn не передавать вовсе.
- Логин панели: при 403 установщик (≥2026-11-06.5) спрашивает логин И пароль
  и сохраняет `ADMIN_USER` в state.
- Проверка панели из установщика проходит даже при неверном ufw-порядке:
  curl идёт с самого сервера (loopback разрешён). Реальную доступность
  проверять снаружи.
- Caddyfile обязан монтироваться в ноду (`/var/lib/caddy/.local/share/caddy
  :/caddy-data:ro`) — Xray читает файл сертификата.
- Нода — отдельный compose-проект (`nsky-node`), `network_mode: host`;
  `--remove-orphans` при общем имени проекта сносит чужие контейнеры.

## 6. Команды эксплуатации (шпаргалка)

- Обновление сервера: скачать скрипт по полному SHA-коммиту, сверить
  sha256, запустить без `--wipe`; `--panel-ip`/`--cascade` подхватываются
  из state, но можно указать явно.
- Диагностика: `bash nsky-install.sh <домен> <email> --check` (панель,
  скрытие /api/sub, каскад, число ссылок, ufw).
- Релей: `bash /root/nsky-relay.sh <NL_IP>` / `--status` / `--remove`.
- Каскад вкл/выкл: тот же запуск установщика с `--cascade <IP>` /
  `--cascade-remove`.
- IP офиса сменился: `ufw allow from НОВЫЙ to any port 8444 proto tcp`,
  `ufw delete allow from СТАРЫЙ to any port 8444 proto tcp`, обновить
  `PANEL_ALLOW_FROM` в state (иначе обновление откатит ручную правку).

## 9. Не повторять ошибки

- Не публиковать инфраструктурные идентификаторы в репозиторий/чат.
- Не запускать сборку/скрипты «вслепую» на production VPS — сначала снимок.
- Не использовать `--remove-orphans`, `alpn: ""`, общий ufw-deny на порт
  панели, `$(...)` для переменных из функций, `[[ ]] &&` последним в блоке
  при `set -e`, `grep` с возможным нулём совпадений в pipefail-скриптах.
- Не коммитить генераты в обход CI-шага: теперь CI регенерирует сам, но
  локальные генераты в `app/lib/models/generated/` могут отставать — при
  добавлении полей в freezed-модели это больше не блокер (шаг в workflow).
