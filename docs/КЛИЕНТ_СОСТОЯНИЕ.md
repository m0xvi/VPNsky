## 1. Главное ограничение

В этой песочнице **нет Flutter, Dart, Go и Rust**. Собрать клиент здесь физически нельзя.
Значит, любая сборка — только через GitHub Actions после того, как исходники окажутся
в вашем репозитории.

Токен `gh` в песочнице имеет доступ **только к `m0xvi/VPNsky`**: форк `chen08209/FlClash`
и создание новых репозиториев через API недоступны (`403 Resource not accessible by
integration`). Поэтому исходники лежат в подкаталоге `app/` этого репозитория, а не в
отдельном форке.

## 2. Что уже лежит в `app/`

FlClash v0.9.3 целиком, с подмодулями, скопированными внутрь как обычные каталоги
(в CI не будет возни с SSH-подмодулями).

```
app/
├── lib/                 365 .dart файлов (UI, состояние, логика)
├── core/Clash.Meta/     Go-ядро, форк mihomo: REALITY, XHTTP, Hysteria2
├── plugins/prism_ui/    UI-компоненты upstream
├── services/helper/     Rust-служба Windows/Linux (TUN без прав администратора)
├── assets/data/         GEOIP/GEOSITE/ASN — вшиты, 46 МБ
└── .github/workflows/build-vpnsky.yml   наша сборка
```

## 3. Внесённые изменения (и почему именно так)

| Что | Где | Причина |
|---|---|---|
| `appName = 'VPNsky'` | `lib/common/constant.dart` | имя в окне и интерфейсе |
| Пакет `ru.vpnsky.client` | `android/`, `macos/` | свой идентификатор в сторах и на устройствах |
| Заголовок окна, метаданные `.exe`, установщик | `windows/` | сотрудник видит VPNsky, а не FlClash |
| Свой `app_id` установщика | `windows/packaging/exe/make_config.yaml` | иначе установка конфликтует с настоящим FlClash |
| Протокол `vpnsky://` | `protocol.dart`, манифесты, `.iss`, `Info.plist` | ссылка на подписку открывается в нашем клиенте |
| Отключено автообновление geo | `lib/models/clash_config.dart` | базы вшиты; GitHub у сотрудников может не открываться |
| Диагностика убрана из мобильного меню | `lib/views/navigation.dart` | сотруднику не нужны «Запросы» и «DNS» |
| Сборка в приватном репозитории | `.github/workflows/build-vpnsky.yml` | upstream отключает CI в приватных репо |

### Чего я НЕ менял (и это важно)

**Технические имена оставлены как в upstream**: `FlClashHelperService`, `/tmp/FlClashSocket_*`,
`\\.\pipe\FlClashCore_*`, `x-flclash-helper-protocol`, имя файла `FlClash.exe`.

Причина: эти строки продублированы в `services/helper/src/service/{windows,linux,hub}.rs`,
в Go-ядре и в нативном коде Android. Переименование только в Dart ломает связь клиента
со службой — TUN на Windows перестаёт подниматься, и это выяснится уже на живом стенде.
Если переименовывать, то синхронно в трёх местах и с проверкой на реальной машине.

Также **не зашит адрес сервера**, как вы и сказали. Доставка подписки — через ссылку
`vpnsky://install-config?url=<адрес>`, которую сотрудник получает от админа (или через QR).
Адрес живёт на сервере и в ссылке, в сборке его нет.

## 4. Что нужно от вас, чтобы получить первый установщик

1. **Запушить `app/` в отдельный репозиторий** (или сделать публичным текущий, чтобы
   подхватились Actions). В песочнице я этого сделать не могу — прав нет.
2. Дождаться DNS и поднять панель в Нидерландах.
3. Выдать первую подписку и собрать ссылку `vpnsky://install-config?url=...`.

## 5. Чего в клиенте ещё нет

- Онбординг «одна кнопка» на первом экране (сейчас — стандартный дашборд FlClash).
- Автоперебор серверов. Реализуется **на сервере**: в подписке группы `fallback`/`url-test`,
  клиент их исполняет. Писать свой перебор в Dart не нужно.
- Баннер `announce` из подписки — ядро его читает, но красивого баннера в UI нет.
- Русские тексты статусов из `lib/common/vpnsky_texts.dart` пока **не подключены** к экрану
  статуса: файл создан, но UI его не использует. Это следующая правка.

## 5.1. Про подпись Android (важно)

В `android/app/build.gradle.kts` логика такая: если `android/app/keystore.jks` и пароли
на месте — release-сборка подписывается вашим ключом. Если нет — **сборка всё равно
пройдёт**, но подпишется debug-ключом и получит суффикс `.dev`:
пакет станет `ru.vpnsky.client.dev`.

Последствия:
- тестовый APK ставится рядом с «боевым», не заменяя его;
- обновить им уже установленное приложение нельзя (разные пакеты);
- в Play/стор его не примут.

Для первой проверки на стенде этого достаточно. Перед раздачей сотрудникам обязательно
задайте четыре секрета (см. раздел 4) — иначе у всех будет `.dev`-сборка.
