# Билайн: что сделать прямо сейчас

Одна страница. Обновлено по результатам первой живой проверки.
**Цель:** телефон на LTE Билайн открывает `2ip.ru` и видит IP Нидерландов.

---

## ⚠️ СТОП: сначала ОДНО действие, без серверных команд

По счётчикам на релее: `tcp dpt:8443` — есть пакеты, `tcp dpt:2053` — **0**,
`udp dpt:443` — **0**. Значит, `NSky XHTTP (RU)` и `NSky Hysteria2 (RU)` ещё
**не пробовались**. А `Hysteria2 (RU)` уже готов к работе: в панели у него порт
443 (UDP), и на релее для `udp/443` DNAT уже стоит. Никаких `iptables` для
этого не нужно.

**Прямо сейчас на телефоне:** Wi-Fi выкл → Happ → вручную выбрать
`NSky Hysteria2 (RU)` → Подключить → открыть `2ip.ru`.

Только если это не сработало — пробовать `NSky XHTTP (RU)`, и лишь потом
переходить к плану Б в конце страницы. План Б заранее делать не надо.

## Итог первой попытки

| Что проверили | Результат |
|---|---|
| `nsky-cascade-check.sh --relay` на русском VPS | **13 ok / 0 ошибок**: `ip_forward`, автозапуск, все 8 правил iptables на месте |
| Счётчик `tcp dpt:8443` на релее | **Вырос** (было ~860, стало ~2030 пакетов) → телефон реально доходит до русского VPS, Билайн его IP не блокирует |
| Панель, тестовый пользователь | Трафик ~450 КиБ и «Последняя нода `nsky-node-1`» → пакеты доходят и до Xray в Нидерландах |
| Подписка в Happ | 6 серверов, `NSky REALITY (RU)` выбран вручную, сквад `Default-Squad` |


`inactive` у `nsky-relay.service` — это норма: юнит типа oneshot применяет правила при
загрузке и завершается. `ufw inactive` при `-P FORWARD ACCEPT` — тоже не ошибка.

## Если Happ пишет «Тайм-аут» при добавлении или обновлении подписки

**Это ожидаемо на LTE Билайн и не означает поломки серверов.**

Ссылка подписки ведёт на зарубежный домен, `443/tcp` нидерландского сервера.
Релей пробрасывает только `8443/tcp`, `2053/tcp` и `443/udp`; **`443/tcp`**
(подписка) и **`8444/tcp`** (панель) через него не идут. Happ при добавлении
ссылки делает обычный HTTPS-запрос напрямую, Билайн его режет, клиент не
дожидается ответа и показывает «Тайм-аут».

**Это не провайдер VPS и не авария.** По уже присланным логам:

| Проверка | Что показала |
|---|---|
| `nsky-cascade-check.sh --relay` на RU | 13 ok / 0 ошибок, правила и автозапуск на месте |
| Счётчик `tcp dpt:8443` на релее | Рос при подключении телефона → входящие порты провайдером не закрыты |
| Панель, тестовый пользователь | Трафик и «Последняя нода `nsky-node-1`» → NL-нода жива |
| Чекер на NL | `HTTP 200` на публичную ссылку → подписка на сервере отдаётся |

Если бы хостинг блокировал порты, счётчики DNAT не росли бы. Разница простая:
**туннель** идёт через релей и работает, а **запрос на обновление подписки**
идёт мимо релея и потому не проходит.

Что делать:

1. **Не добавлять и не обновлять подписку по LTE.** Закрыть окно с таймаутом.
2. Если карточка с 6 серверами ещё есть — просто выбрать `NSky Hysteria2 (RU)`
   и подключить. Обновление **не требуется**: конфиг на сервере не менялся,
   кэш подписки действителен.
3. Если карточка удалена — добавить ссылку **один раз из другой сети**
   (домашний Wi-Fi, точка доступа от другого оператора), затем вернуться на LTE.
4. Если другой сети нет: в панели (машина D) `Users → карандаш → More actions
   → Subscription links` взять «сырую» строку `hysteria2://` для хоста `(RU)`
   и добавить её в Happ вручную через «+» / «из буфера» / QR. Такой профиль
   не делает запрос к зарубежному домену и таймаута не даёт.

> Проксировать `443/tcp` подписки через русский VPS технически можно, но это
> отдельная доработка, и она **конфликтует с планом Б** (тот же порт `443/tcp`).
> Не начинайте её, пока не проверено само подключение.

**Что ломается:** Happ пишет «Ошибка TLS рукопожатия», браузер — «Адрес не найден».
Пакеты на 8443 в основном мелкие (≈60 байт в среднем): это повторные попытки
рукопожатия/сбросы, а не устойчивый поток данных. То есть **труба собрана,
но REALITY-handshake на LTE не проходит**.

Проверил код установщика: хосты `(RU)` — точные копии прямых, отличается только
`address`; SNI, порты, ключи и shortId те же. Кривого хоста нет.

## Сейчас НЕ делать

- ротацию `SUB_SECRET`, сброс пароля администратора — собьют ссылку на телефоне;
- `nsky-install.sh --wipe` и **любой повторный запуск `nsky-install.sh`**:
  он при каждом запуске заново генерирует приватный ключ REALITY, `shortId` и
  путь XHTTP, чем делает все уже выданные подписки недействительными;
- правку хостов, панели, профиля Xray;
- обновление подписки по LTE (ссылка живёт на зарубежном домене, `443/tcp`
  через релей не пробрасывается).

## Шаг 0. Обновить подписку по Wi-Fi (2 минуты)

Кэш в Happ датирован 14:13. Если после этого на NL что-то менялось, на телефоне
остались старые `pbk`/`sid` — это ровно и даёт «Ошибка TLS рукопожатия».

1. Включить Wi-Fi, открыть Happ.
2. На карточке `Remnawave` нажать **иконку обновления** (две стрелки); дождаться
   новой метки времени.
3. Wi-Fi **выключить**, LTE оставить. Подписку больше не трогать.

## Шаг 1. Перебрать протоколы — начинаем с UDP

На LTE по очереди выбирать **вручную**, каждый раз проверяя `2ip.ru`:

```
NSky Hysteria2 (RU)
NSky XHTTP (RU)
NSky REALITY (RU)
```

Именно в таком порядке: `Hysteria2 (RU)` идёт по **UDP/443**, который мобильный
DPI трогает гораздо реже, чем нестандартный TCP/8443. `н/д` в колонке пинга у
`REALITY`/`XHTTP` — не ошибка, задержку через «сырой» TCP-прокси часто не
померить; ошибка, когда из-за неё включён автовыбор и берётся не `(RU)`.

Автовыбор / «лучший по пингу» должен быть **выключен**, выбранная строка —
подсвечена. Надпись «ПОДКЛЮЧЕН» сама по себе ничего не доказывает.

## Шаг 2. Смотреть счётчики на русском VPS

До попытки и сразу после (подержать 10 секунд):

```
iptables -t nat -L PREROUTING -nv
```

| Что выросло | Вывод |
|---|---|
| `udp dpt:443` | Hysteria2 дошёл до релея; если `2ip.ru` всё равно не открылся — смотреть логи ноды на NL и DNS |
| `tcp dpt:2053` | XHTTP дошёл; та же логика |
| только `tcp dpt:8443`, данные не идут | DPI Билайна рвёт именно TCP/8443 + REALITY → план Б |
| ничего не растёт | выбран не `(RU)` или не тот профиль → вернуться к шагу 0 |

## Шаг 3. Две быстрые проверки на телефоне

Обе могут дать ровно «TLS handshake error» при исправном сервере:

1. **Приватный DNS / «Защищённый DNS»** в настройках Android → выключить
   («Автоматически» или «Откл.») на время теста: DoT/DoH уходит мимо туннеля и
   даёт «Адрес не найден».
2. **Дата и время** → «Автоматические»: при сбитых часах TLS-сертификат
   отклоняется. Также убедиться, что не включён второй VPN/«безопасный DNS»
   от оператора.
3. Если в настройках Happ/TUN есть поле **MTU** — поставить `1280`: у LTE часто
   меньше MTU, и крупный TLS ServerHello не проходит.

## План Б: перевесить REALITY (RU) на порт 443/tcp

Если все три протокола дают TLS-ошибку, почти наверняка дело в нестандартном
`8443/tcp`. На русском VPS `443/tcp` **свободен** (релей занимает только
`443/udp`), а на NL REALITY слушает `8443`. Значит, можно принять соединение на
обычном HTTPS-порту и перенаправить его туда же.

План Б состоит ровно из **трёх** шагов в двух местах. Не пропускайте ни один:
мало поменять порт в панели — надо ещё добавить правило на релее, и наоборот.

**Шаг Б1 — русский VPS (машина B), одна строка:**

Вставьте в PuTTY **только эту строку** и нажмите Enter. Переменные не нужны:

```
iptables -t nat -A PREROUTING -p tcp --dport 443 -j DNAT --to-destination $(cat /opt/nsky-relay/nl-ip):8443
```

Вставлять строго по одной строке: после вставки Enter, и только потом следующая
команда. Если в строке промпта появился мусор вроде `ROUTING -p tcp ...` —
нажмите `Ctrl+C` и повторите сначала: это PuTTY склеил вставку, команда **не
выполнилась**.

Проверка, что правило добавилось (вторая строка, отдельно):

```
iptables -t nat -S PREROUTING | grep 'dport 443'
```

Должна появиться строка с `--dport 443` и `--to-destination <IP>:8443`. Не
появилась — правило не добавлено, повторите шаг Б1.

Существующие `FORWARD` (tcp 8443,2053 к NL) и `MASQUERADE` уже подходят: после
DNAT порт назначения становится 8443. `udp/443` и `tcp/443` не конфликтуют —
это разные протоколы.

**Шаг Б2 — панель в браузере (машина D):**

`Management → Hosts` → строка **`NSky REALITY (RU)`** → карандаш → поле
**Port** заменить на `443` → Save. Остальные пять хостов не трогать.

**Шаг Б3 — телефон:**

Включить Wi-Fi → Happ → обновить подписку → Wi-Fi выключить → выбрать
`NSky REALITY (RU)` → `2ip.ru`. Пока подписка не обновлена, в Happ останется
старый порт 8443 и правило Б1 не будет использоваться.

> Правило Б1 временное, потеряется при перезагрузке. Если поможет — добавим его
> в `nsky-relay.sh`/systemd и в чекер, чтобы стало постоянным.
