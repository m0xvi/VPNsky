# Билайн: что сделать прямо сейчас

Одна страница. Идём по порядку и никуда не сворачиваем. **Цель:** телефон на
LTE Билайн открывает `2ip.ru` и видит IP Нидерландов.

---

## Сейчас НЕ делать

Эти вещи собьют ссылку на телефоне и добавят путаницы — отложить до победы:

- ротацию `SUB_SECRET`, сброс пароля администратора;
- `nsky-install.sh --wipe`, переустановку, правку панели и хостов;
- обновление подписки по LTE (ссылка живёт на зарубежном домене);
- любые команды не на той машине (см. ниже).

---

## Шаг 1. Машина B — русский VPS (`msk-…`), один раз

Проверить, что правила релея на месте и переживут перезагрузку. Одна строка,
вставлять в PuTTY целиком; если склеилось — `Ctrl+C` и повторить:

```
curl -fsSL -o /root/nsky-cascade-check.sh https://raw.githubusercontent.com/m0xvi/VPNsky/2ad3e4b8007b8ee6a3aa3efe2d5ba29d34a64fc2/deploy/nsky-cascade-check.sh && bash /root/nsky-cascade-check.sh --relay
```

Ждём `ошибок: 0` и `8 правил`. Если есть `✗` — применить правила заново:

```
bash /root/nsky-relay.sh
```

(IP подставится сам из `/opt/nsky-relay/nl-ip`.)

---

## Шаг 2. Машина C — телефон

1. Wi-Fi **выключить**, мобильный интернет Билайн **включить** (в строке состояния `4G`).
2. Открыть Happ. Подписка `Remnawave` уже добавлена — **не удалять и не обновлять**.
3. **Выключить автовыбор** («лучший по пингу» / Auto). На скриншотах у прямых
   серверов пинг есть, у `(RU)` — `н/д`, поэтому автовыбор берёт прямой
   зарубежный сервер, который Билайн и режет.
4. Нажать на строку **`NSky REALITY (RU)`** и убедиться, что она **выбрана**
   (отметка/подсветка), а не просто открыт список.
5. Нажать «Подключить», подождать 10–15 секунд.

Надпись «ПОДКЛЮЧЕН» **ничего не доказывает** — она означает только то, что
поднялся локальный VPN-интерфейс.

---

## Шаг 3. Машина C — проверка

Открыть в браузере телефона:

```
https://2ip.ru
```

- **Нидерланды** → готово, каскад работает. Дальше можно пробовать 2053/tcp и
  443/udp и уже потом заниматься ротацией секрета.
- **Билайн / РФ** или страница не открывается → шаг 4.

---

## Шаг 4. Машина B — счётчики (самый важный диагноз)

На русском VPS, **до** нажатия «Подключить» на телефоне:

```
iptables -t nat -L PREROUTING -nv
```

Подключить на телефоне, подержать 10 секунд, повторить ту же команду.

| Счётчик `dpt:8443` | Что это значит | Что делать |
|---|---|---|
| **Растёт** | Пакеты до релея доходят, DNAT работает | Смотреть NL: `docker logs --tail 30 remnanode`; проверить DNS в Happ; шаг 5 |
| **Стоит** | Либо выбран не `(RU)`, либо Билайн режет сам IP/порт русского VPS | Вернуться к шагу 2 п. 3–4, затем шаг 5 |

---

## Шаг 5. Машина C — перебор протоколов

По очереди, каждый раз выбирая вручную и проверяя `2ip.ru`:

```
NSky REALITY (RU)
NSky XHTTP (RU)
NSky Hysteria2 (RU)
```

И для контроля — прямой `NSky REALITY`. Начинать именно с REALITY (RU):
у него SNI `www.microsoft.com`, а у Hysteria2 (RU) — зарубежный домен, для
мобильного DPI это разные профили.

`н/д` в колонке пинга у `(RU)` само по себе не ошибка: через «сырой»
TCP-прокси задержку часто не померить. Ошибка — когда приложение из-за
этого выбирает не тот сервер.

---

## Что прислать, если не заработало

Три факта, без доменов, IP, паролей и ссылок:

1. Какой IP/страну показал `2ip.ru` при выбранном `NSky REALITY (RU)`.
2. Рос ли счётчик `dpt:8443` на русском VPS.
3. Какой из шести серверов был выбран и что написал Happ при подключении.

Этого достаточно, чтобы сказать, где именно рвётся: на телефоне, на русском
VPS или на нидерландской ноде.
