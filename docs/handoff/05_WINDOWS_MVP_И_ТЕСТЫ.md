# Windows: первый этап и критерии готовности

## Цель первой проверяемой версии

Рабочая Windows 10/11 x64 сборка, запускаемая сотрудником; простой экран; в тестовом контуре позволяет импортировать или получить разрешённую конфигурацию, установить VPN в TUN-режиме и проверить доступность через туннель по существующим VLESS + REALITY и Hysteria2. Внешний вид и контроль должны учитывать будущие Android/iOS. Не называть экран-заглушку или системный прокси полноценным VPN.

Это MVP, не production для 50+ человек. До него отдельно определить, какие функции включены в тестовую сборку: временный импорт существующего тестового профиля допустим, даже если полностью управляемая активация будет следующим этапом. Не представлять импорт подписки как уже работающий собственный сервер удалённого управления.

## Порядок работ

1. Выяснить Windows сборку/архитектуру, админ-права на тестовом ПК, предпочтения по лицензии, GitHub-репозиторий и условия распространения. Уточнить, каким существующим тестовым аккаунтом можно безопасно пользоваться; не запрашивать секретный URI в чат.
2. Воспроизводимо собрать один выбранный открытый upstream в Actions. Сравнить с чистой upstream-сборкой, выписать commit, версии инструментов/ядра и зависимости. Проанализировать лицензии. Ничего не применять к production VPS.
3. Запустить этот бинарник на тестовом Windows 10 и Windows 11, последовательно проверить текущие протоколы и сети. Если VLESS не работает, разбирать достижимость, импорт, версии, соединение, handshake, TUN и выход по этапам, с обезличенными категориями; не делать вывод «виноват оператор» без сравнения.
4. Форкнуть или сделать свой UI, сохраняя работающее ядро. Один главный экран, состояния, диалог разрешения, подключение/отключение, диагностика, информация о версии; секреты не отображать. Не удалять нативные службы/драйверы без проверки.
5. Подключить обработчик конфигурации и безопасное хранение. Сначала допускается ручная установка тестового профиля, затем активация и control plane. Для реального протокольного failover нужна реализация с проверкой результата; сначала можно позволить администратору выбирать протокол и ясно маркировать отсутствие автоматики.
6. Сделать draft/prerelease из защищённого тега, полный набор файлов, checksum, инструкции и ограничения; установить на чистые тестовые машины. Затем пилот на нескольких согласованных пользователях без замены старого клиента/профиля.
7. После стабилизации Windows — решить Android; iOS — только затем. Совместимость iOS и лицензий оценить до архитектурной фиксации, а не перед самой публикацией.

## Проверочная матрица

| Область | Что измерить/ожидаемый результат |
|---|---|
| Установка | Чистые Windows 10 и 11 x64; верная версия и все зависимости; требуется ли админ для TUN; честное сообщение при отказе UAC; отсутствие изменений до согласия пользователя. |
| UX | Пользователь без инструкции может активировать/импортировать, подключить, увидеть реальный статус и отключить. Нет технических секретов на экране и в отчёте. |
| VLESS REALITY | С указанными версиями сервера и клиентского ядра реальный запрос к известной проверочной цели идёт через туннель. Сравнить работу нескольких сетей при необходимости. |
| Hysteria2 | UDP handshake и реальный запрос через туннель; проверить и стабильный обмен. Ошибка при недоступном UDP понятна. |
| Full tunnel | Обычные браузеры и приложения, не использующие системный прокси, идут через VPN; внешний адрес/маршрут проверен по доверенному контрольному endpoint. Проверить и VPN-серверный трафик — чтобы не сделать рекурсивный туннель. |
| DNS и IPv6 | Проверить DNS по документированной политике, IPv4 и IPv6 утечки/недоступность, локальные и корпоративные имена; тестировать реальную конфигурацию каждого ПК. Не обещать, что одна DNS-проверка докажет отсутствие всех утечек. |
| Сети | Интернет пропал/вернулся, Wi‑Fi ↔ проводная сеть/раздача, sleep/wake, перезагрузка, новый IP, конфликт другого VPN. Туннель восстанавливается в рамках документированного режима. |
| Отказ протокола | Блокировка/недоступность одного из транспортов в контролируемом тесте → ожидаемый переход на другой, если failover реализован; без бесконечного переключения. Один IP/VPS остаётся общим риском. |
| Отключение | Закрытие приложения, штатное отключение и деинсталляция не оставляют неожиданные маршруты/прокси/драйверы; заранее согласовать, если fail-closed обязан оставаться активным. Должна быть инструкция аварийного восстановления. |
| Kill switch | Только если реализован: запрет утечки при обрыве ядра, падении приложения, sleep/wake и reboot, исключения для control plane, аварийное восстановление. Если не тестирован/не реализован — явно описать, что выход напрямую возможен. |
| Удалённая конфигурация | Неизвестная версия, плохой JSON, ошибка TLS, повторная версия, откат, потеря связи — прежний рабочий конфиг сохраняется; токены не в логах/URL. Проверить поведение при старте без сети. |
| Отзыв | Отдельно: отключение доступа к API и отзыв серверных VPN-ключей; уже установленная сессия и новые подключения — наблюдаемое поведение. Нельзя выдавать HTTP 403 от подписки за отзыв VPN-доступа. |
| Секреты | Проверить исполняемый файл, логи, crash dumps, Windows Event Log, артефакты и релиз; персональные VPN-данные и activation URI отсутствуют. Fixtures синтетические. |
| Подпись/поставка | Информация о неподписанном prerelease, SHA-256, целостность всех файлов; для production Authenticode и процедура проверки происхождения. |

Один тестовый профиль и одно устройство не доказывают устойчивость для 50+ сотрудников. Отдельная нагрузочная и сетевую проверку сервера планировать позже; ни тайм-ауты соединений, ни состояние сервисов сами по себе не идентифицируют причину.

## Документируем каждый тест

Дата/время и часовой пояс; ОС и версия приложения; версия каждого ядра и серверного ПО (при безопасном получении); сеть и оператор; профиль/протокол без секретов; сценарий; ожидаемый и фактический результат; category ошибки и ссылка на обезличенный отчёт. Нельзя просить у пользователя прислать полный конфиг, QR, ссылку подписки или исходный необработанный журнал.

## Границы готовности

- `BUILD OK` — только собранный файл.
- `MVP работает` — пройдены обязательные тесты одного согласованного сценария на Windows.
- `Готов к пилоту` — сетевые, recovery и безопасность для тестовой группы проверены, есть откат.
- `Production` — подтверждены безопасность, подписание, обновления, операционная поддержка, мониторинг и план инцидентов, а также испытания на реальных условиях компании. Уровни не смешивать.
