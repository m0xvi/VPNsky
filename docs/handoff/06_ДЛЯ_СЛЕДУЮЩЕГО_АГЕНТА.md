# Стартовая инструкция следующему агенту

## Можно вставить в новый диалог

> Изучи весь приложенный архив, начиная с `00_ПРОЧИТАТЬ_СНАЧАЛА.md`. Я хочу новый надёжный, простой корпоративный VPN-клиент и систему удалённого управления на открытых компонентах. Используем только существующий VPS. Код и релизы — через GitHub и GitHub Actions. Очерёдность: сначала Windows 10/11, затем Android, затем iOS. Работай по-русски. Никаких необратимых действий на VPS, смены VPN-конфигурации или переноса существующих пользователей без согласованного плана, backup и моего явного подтверждения. Сначала уточни GitHub-доступ и юридические/платформенные ограничения, сравни кандидатов и предложи реальный план первой Windows-сборки. Не проси секреты в чат. Различай проверенное и предположения.

## Что спросить в начале, не превращая это в длинную анкету

1. GitHub: организация/имя существующего или нового репозитория, private/public, желаемый способ доступа и возможность Actions. Встроенный коннектор прошлой сессии был unsupported; проверить состояние в новой. Не просить токен в диалог. Для действий в GitHub спросить явное разрешение.
2. Лицензия/распространение: только одна компания или предполагаются другие организации/продажа; допустимо ли по лицензии предоставить изменённый исходный код получателям; нужно ли закрывать свой UI; как сотрудники получат приложение. Подходящий ответ не заменяет проверки лицензии.
3. Windows-пилот: конкретные Windows 10/11 (сборка, архитектура), доступ администратора/UAC на тестовой машине, можно ли использовать существующий выделенный тестовый профиль **без передачи секретов**. Не создавать клиента автоматически из-за не до конца проверенного генератора Xray.

Обсудить позже, но до выбора архитектуры: есть ли Mac, Apple Developer Program organization, корпоративная MDM или личные iPhone; организация и политика полного туннеля/локальной сети, режим kill switch, желаемый дизайн. Не блокировать подготовку Windows-исследования отсутствием Apple-аккаунта.

## Первые действия, которые можно выполнить безопасно

- Прочитать документы и ссылки, перепроверить доступные актуальные версии исходников/лицензий и разработать короткую сравнительную таблицу конкретных commit/tag.
- Проверить возможности доступа к GitHub и Actions. Создавать fork/репозиторий и делать push только с согласия и известного аккаунта. Если доступа нет, дать понятные пошаговые действия или готовые файлы, не говорить, что релиз опубликован.
- Изучить существующие репозитории и их Windows build workflow read-only. Оценить, как построены ядро, TUN/драйвер, DNS, iOS и обновление, наличие закрытых бинарников и лицензии. Не исполнять неизвестный код и не выполнять установочные `curl | bash` на production VPS.
- При разрешении на использование GitHub — создать ветку и сначала добиться сборки **неизменённого** upstream на Windows runner; приложить логи/ссылки на успешный run. Выпустить тестовый draft/prerelease только после согласования.
- На VPS без отдельного подтверждения — исключительно read-only инвентаризация без раскрытия секретов. Если тестировать реальным профилем, профиль должен вводиться на тестовом устройстве и не попадать в CI/чат/логи. Использовать уже имеющийся VPS и текущее разрешённое тестовое соединение.
- Постепенно менять интерфейс и функциональность, документируя изменения. Не отправлять большой код прямо в SSH одним фрагментом: прошлые вставки длиннее ~2 КБ обрезались.

## Чего агент НЕ должен заявлять

- Что клиент уже создан, Actions настроены, релиз опубликован, исходник или сервер изменены — пока это не выполнено и не проверено.
- Что Hiddify/sing-box, Билайн, РКН или MTU точно являются причиной. Локальный VPS-тест VLESS доказал только локальный туннель одного клиента.
- Что VPS очищен от Amnezia; что система отзыва индивидуальных Hysteria2-ключей работает; что новая версия логов установлена окончательно; что счётчики трафика исправлены.
- Что новый интерфейс предотвращает IP-блокировки/полное отключение мобильной сети либо гарантирует полное отсутствие утечек.
- Что всякий проект open source можно форкнуть, закрыть и распространять без выполнения условий лицензий.
