# Передача следующему агенту: корпоративный VPN-клиент

Состояние на 5 ноября 2026 года. Архив — рабочая записка и материалы прошлой сессии, а не готовое приложение, серверная конфигурация или workflow. Данные могли устареть: перед действиями проверять фактическое состояние. В архиве нет намеренно включённых паролей, VPN-ключей, токенов, журналов клиентов, SSH-ключей или сертификатов. IP, домен, имена файлов и внутреннее устройство сервера включены: считайте архив служебным, не выкладывайте его в публичный репозиторий без решения владельца.

## Задача от пользователя

Пользователь хочет **начать разработку корпоративного VPN-продукта с чистого листа**: надёжный, удалённо управляемый, максимально простой для сотрудников. Желательно брать готовые качественные open-source компоненты, в том числе многопротокольное ядро. Нужны Windows 10/11, Android и iPhone. Очерёдность: **Windows → Android → iOS**. Исходный код и выпуск релизов — через GitHub и GitHub Actions. Целевой масштаб — 50+ сотрудников. Сначала собрать и проверить Windows-версию, только затем переходить к Android и iOS; заранее учитывать iOS в архитектуре и будем ставить самостоятельно через кабель на каждое устройство, лицензия не нужна.

## Что находится в архиве

1. `01_СОСТОЯНИЕ_VPS.md` — топология, доказанные результаты, ограничения и нерешённые проблемы.
2. `02_АРХИТЕКТУРА_И_БЕЗОПАСНОСТЬ.md` — целевое поведение, дизайн control plane, безопасность, миграция.
3. `03_ВЫБОР_ОТКРЫТОГО_КОДА.md` — кандидаты, лицензии и вопросы выбора.
4. `04_GITHUB_ACTIONS_И_РЕЛИЗЫ.md` — CI/CD, Windows, Android, iOS и защита поставки.
5. `05_WINDOWS_MVP_И_ТЕСТЫ.md` — конкретные этапы, acceptance matrix и критерии допуска.
6. `06_ДЛЯ_СЛЕДУЮЩЕГО_АГЕНТА.md` — стартовый промпт, вопросы и первые безопасные шаги.
7. `07_ИСТОЧНИКИ.md` — ссылки на первоисточники и границы достоверности.
8. `08_СПРАВОЧНЫЕ_ФАЙЛЫ/` — ранее подготовленная диагностическая программа с инструкцией; код фильтрованных протокольных отчётов. Это ИСТОРИЧЕСКИЕ материалы, не готовая установка; серверные версии могут отличаться. В архив не включены прежние разрушительные установщики, архивы бэкапов, сырые логи, профили, скриншоты и клиентские данные.
9. `SHA256SUMS.txt` — контрольные суммы файлов архива (кроме самого списка).

## Приоритеты и рекомендации

1. Сначала составить и зафиксировать решение о лицензиях и распространении. Не выдавать GPL за лицензию, позволяющую автоматически закрыть производный код. Провести выбор на текущих версиях; форк Karing + sing-box — хороший **кандидат на проверку**, не гарантированный выбор.
2. Сразу проверить GitHub-доступ, выбрать владельца/репозиторий и безопасную модель распространения бинарников. В этой сессии проверка встроенного коннектора GitHub вернула `unsupported`; репозиторий, Actions и релизы не созданы. Это не устанавливает, какие возможности будут у следующего агента или у пользователя через браузер/CLI.
3. Windows-версия первой: сначала проверить сборку выбранного upstream без изменений; затем минимальный интерфейс и реальный туннель VLESS/REALITY и Hysteria2. Доказать работу на реальном Windows 10/11, а не объявлять CI-сборку проверкой сети.
4. На раннем этапе можно тестировать существующие разрешённые профили без замены и создания клиентов. Никогда не пересылать реальные URI/UUID/пароли в чат, Issues, логи CI или архивы.
5. Только после Windows-пилота — Android, после него — iOS. На каждом этапе подтвердить успешное подключение и восстановление, а не только наличие файла сборки.

## Важные отличия

- Открытый VPN-клиент не устраняет блокировку IP, сбой маршрута или ограничения мобильного оператора. Один сервер остаётся единой точкой отказа.
- Подписка обычно обновляет только то, что конкретное приложение умеет импортировать; она не равна полноценному удалённому управлению приложением.
- QR/временная страница — механизм выдачи, а долгосрочный токен устройства — отдельный секрет. Отзыв токена обновления не отзывает уже выданные VPN-учётные данные.
- Не считать старый локальный серверный шаблон фактической конфигурацией VPS. Пакет содержит только безопасно описанное состояние, актуальные файлы надо изучать с редактированием секретов.
- Работа на русском языке. Для команд в PuTTY давать короткие отдельные блоки: длинные вставки ранее обрезались.
