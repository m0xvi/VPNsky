# Существующий VPS и история диагностики

## Известная топология (снимок предыдущей сессии, не гарантия текущего состояния)

- Тестированный VPS: `ams-1-vm-1ksc`, IP `186.246.71.231`, домен `rknmrz.xyz`; провайдер по прежним проверкам — Timeweb TW-Cloud.
- VLESS + REALITY: Xray, TCP/443. Hysteria2: отдельный `hysteria-server`, UDP/443. По прежним данным nginx слушает `127.0.0.1:8443`, Xray Stats API `127.0.0.1:10085`. Обычный HTTPS на домене работает через имеющуюся схему; проверить фактическую конфигурацию, прежде чем что-то переносить.
- Telegram-бот, индивидуальные ссылки, HTML-страница клиента и её продление. Секреты/прокси бота — `/root/vpn-telegram.env` (`TG_TOKEN`, `TG_CHAT_ID`, `TG_PROXY_LINK`, `BOT_API_PROXY`); не показывать их значения и не заводить mtg.
- `/etc/cron.d/vpn-watchdog`: ранее каждые две минуты вызывал `/usr/local/bin/vpn-watchdog` для неактивных xray/hysteria/nginx. `vpn-safe-monitor.timer` тоже установлен и работал, тестовое сообщение было отправлено. Сначала выяснить, какие компоненты активны; не добавлять конкурирующий рестарт или уведомления.
- Отчёты должны фильтроваться **до отправки в Telegram**, быть разделены по протоколам и информативны, без чувствительных данных. Кнопка называется «Логи» без эмодзи. Фильтрация группы не означает, что сырые журналы на сервере безопасны; проверить права, retention и источники.
- На момент проверки в CSV и Xray числился 41 активный клиент, отсутствующих в Xray — 0. Позднее пользователь мог что-то менять; актуальное количество неизвестно. Были проверены 41 `.txt`, 0 некорректных токенов и одна HTTP-подписка 200. Сама по себе доступность подписки не доказывает работоспособность VPN.

## Что доказано и чего не доказано

1. Открытие `https://rknmrz.xyz/` без VPN на Билайне прошло сразу. Это доступность страницы, не доказательство доступности VPN на том же порту.
2. Ключевая пара REALITY на сервере совпала; домен разрешился; у 41 активного клиента не было отсутствующих short ID. Данные конкретного телефона при этом не сравнивались.
3. `/root/vless-check/probe.py` на VPS проверил прямой запрос и VLESS/REALITY через локальный Xray-туннель для одного выбранного клиента: оба `curl=0 HTTP=204`. Повтор для клиента №1 также дал оба 204. Это доказательство только для проверенного профиля и маршрута с VPS, **не тест реального пути с Билайна или клиента Windows**.
4. Android Hiddify 4.1.1 давал VLESS timeout и по подписке, и по прямому ключу; v2rayNG тоже показывал `context deadline exceeded`. Скриншоты разных моментов — нельзя считать одну сеть, одни версии и идентичные профили установленными. Через Hysteria2 телефон подключался, но YouTube и X работали через раз.
5. Клиентский эксперимент с фрагментацией v2rayNG предлагался, но его результата нет. Не считать его успешным или доказательством блокировки.
6. Windows: обычный DNS и `--resolve` дали 24 HTTP 200; TCP 22/443 открывался, но SSH зависал после `SSH2_MSG_KEXINIT sent`; в одном случае помогла раздача телефона. Arena ранее получила SSH host key. Fail2ban работал, совпадение внешнего IP пользователя с баном не установлено; пользователь сказал, что предложенный вариант с Fail2ban не помог. Причина SSH и MTU/PMTU не доказаны.
7. После перезагрузки службы были active, NRestarts=0; нагрузка, диск, RAM и conntrack не давали явной критической причины. Это состояние только на момент замера.

## Конкретные незавершённые вопросы

- Дублированные Xray `email` приводили к `User тест already exists`, Xray рестартовал; `/root/fix-xray-now.py` применён дважды, Xray запускался. В `/root/gen-subs.py` подтверждена конструкция `c["name"] + "_" + c["uuid"]`. Полный цикл добавления нового клиента после правки **не проверен**. Патч не следует повторять: старый фрагмент является подстрокой нового, повтор может быть неидемпотентен. Не считать исправление подтверждённым для всех случаев.
- В локальном шаблоне было дублирование адреса в Telegram share URL. Серверная версия/патч не подтверждены; старые кнопки в уже отправленных сообщениях не изменятся.
- Предыдущий YAML имел `GEOSITE,category-ru,DIRECT`, `GEOSITE,private,DIRECT`, `GEOIP,RU,DIRECT`, `MATCH,PROXY`: это не полный туннель. Текущая потребность — весь трафик через VPN; политику исключений согласовать.
- Локальный шаблон генератора использовал общий Hysteria2-пароль. Фактическую схему на VPS необходимо проверять. Если пароль общий, индивидуально отозвать одного клиента в старой схеме нельзя простым удалением его подписки.
- Кнопка «Трафик» отложена пользователем. Xray Stats API в одном тесте отвечал успешно, но имел 0 счётчиков при 41 клиенте; считать это отсутствием трафика нельзя. Не тратить время на переделку учёта без нового поручения.
- Раздельный отчёт VLESS за 10 минут: 25 записей, распознаваемых событий нет; это не доказывает исправность или неисправность. Часовой отчёт Hysteria: 120 подключений, 30 клиентских отключений, 87 timeout-отключений, 286 TCP timeout, 15 TCP reset, 66 прочих TCP-ошибок. Категории могут пересекаться; не считать их отдельными пользователями и не приписывать текущему телефону без корреляции.
- Новая версия модуля раздельных логов, SHA-256 `b9999e4e528e731ec586036a5bc912d29f48be4105ac1488b99e76ec8a4e69c0`, была передана. Новый отчёт указывает на вероятную установку, но пользователь не прислал отдельный вывод установки. Код включён в архив исключительно для анализа.

## Чего не повторять

- Не считать, что серверный `/root/gen-subs.py` идентичен локальному шаблону, не придумывать отсутствующие флаги `--apply`, `--restart`, `PREVIEW`.
- Не отключать Fail2ban или SSH-пароль вслепую; не менять ядро Xray, `minClientVer`, firewall, порты и VPN-параметры для всех пользователей без диагностики, бэкапа и согласования.
- Не утверждать, что поставлена заглушка сайта или выполнено удаление старого Amnezia: в предыдущей сессии подготовка/инструкции и фактическая установка различались. Ранее пользователь требовал убрать серверный Amnezia из Docker и его watchdog после бэкапа, но выполнение не подтверждено. Сначала инвентаризация.
- 10 минут относятся к ссылке/странице, а не к VPN-ключу; не гарантировать точное удаление старых страниц после остановки бота.
- Не принимать `systemctl active`, HTTP 200 обычного сайта или пинг TCP как доказательство полного прохождения трафика через VPN.
