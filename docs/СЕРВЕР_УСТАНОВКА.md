# Установка сервера NSky

Один скрипт ставит всё: панель, HTTPS, профиль Xray с тремя протоколами,
хосты, ноду и тестовую учётку. Ниже — что нужно сделать до запуска и как
проверить результат готовыми клиентами.

Домен: `oijas.rknmrz.xyz` → `147.45.152.7`.

---

## Шаг 0. Точка восстановления (сделать до установки)

Три уровня отката, от лучшего к худшему.

### Уровень 1 — снапшот диска (лучший)

1. Панель хостинга → ваш сервер → **Snapshots** → **Create snapshot**.
2. Дождаться статуса «готов».

Откат = восстановление снапшота целиком: система, данные, Docker.
Сделайте это **до** установки, пока система чистая. Снапшот живёт вне диска,
поэтому переживает любые ошибки в скрипте.

### Уровень 2 — снимок конфигов (делает скрипт сам)

Перед изменениями скрипт сохраняет в `/opt/nsky/backups/`:

- `before-*.tar.gz` — конфиги firewall, sshd, Caddy, Docker, hosts;
- `КАК_ОТКАТИТЬ.txt` — пошаговая инструкция отката.

### Уровень 3 — вручную

```bash
sudo mkdir -p /root/backups
sudo tar -czf /root/backups/before-nsky-$(date +%F).tar.gz --absolute-names /etc /opt 2>/dev/null
```

## Шаг 2. Запуск установки

Одна команда — с любого сервера, файл скачается сам:

```
cd /opt && curl -fsSL -o nsky-install.sh https://raw.githubusercontent.com/m0xvi/VPNsky/arena/998588fa-vpnsky/deploy/nsky-install.sh
```

```
bash /opt/nsky-install.sh oijas.rknmrz.xyz admin@example.com
```

`admin@example.com` замените на свой e-mail — он нужен Let's Encrypt
для сертификата. Время установки: 5–12 минут, из них большая часть —
скачивание образов.

### Другие режимы

| Команда | Что делает |
|---|---|
| `bash nsky-install.sh <домен> <email>` | установка; повторный запуск безопасен |
| `... --wipe` | снести всё и поставить заново (данные панели удаляются) |
| `... --check` | только диагностика, ничего не меняет |

Повторный запуск без `--wipe` не перезаписывает пароли и не пересоздаёт ноду:
профиль обновляется по тегам инбаундов, UUID сохраняются.

## Что именно ставится

**Порты.** 443/tcp занят Caddy — он отдаёт панель по HTTPS. Поэтому туннели
разведены и не конфликтуют:

| Протокол | Порт | Зачем |
|---|---|---|
| VLESS + REALITY | `8443/tcp` | основной, маскируется под `www.microsoft.com` |
| VLESS + XHTTP | `2053/tcp` | выживает там, где REALITY режут |
| Hysteria2 | `443/udp` | быстрый на мобильных и плохих сетях |
| Панель (Caddy) | `443/tcp` + `80/tcp` | HTTPS, Let's Encrypt |
| Нода | `2222/tcp` | служебный канал панель ↔ нода |

**Hysteria2 требует настоящий TLS-сертификат.** Xray не поднимает этот инбаунд
без TLS, поэтому скрипт монтирует сертификат Caddy в панель (`/caddy-data`) и
передаёт путь в конфиг. Если сертификат ещё не выпустился, Hysteria2 **не
добавляется** — чтобы не уронить всю ноду. Перезапустите скрипт, когда
HTTPS заработает, и протокол добавится.

**Хосты.** Без них панель отдаёт пустую подписку с текстом «No hosts found».
Скрипт создаёт три хоста — по одному на протокол.

**Сквад.** Внутренний сквад выдаёт пользователям доступ к нодам. Скрипт создаёт
его и привязывает все инбаунды.

## Шаг 3. Проверка готовым клиентом

Скрипт в конце печатает ссылку вида
`https://oijas.rknmrz.xyz/api/sub/<uuid>` и тестовую учётку `nsky-test`.

1. Установите **Happ** (Windows) или **v2rayNG** (Android).
2. Добавьте подписку по ссылке.
3. Должно появиться 2–3 сервера, по одному на протокол.
4. Подключитесь и откройте `https://ipinfo.io` — страна должна быть вашей.

Если серверов нет:

```
bash /opt/nsky-install.sh oijas.rknmrz.xyz admin@example.com --check
```

Диагностика покажет состояние ноды, число хостов, число ссылок в подписке и
последние строки лога ноды.

## Шаг 4. Первые пользователи

1. Панель → **Users** → **Create user**.
2. Скопируйте ссылку подписки из карточки пользователя.
3. Передайте её сотруднику — вставить в клиент можно вручную или QR-кодом.

Адрес сервера в приложение не зашивается: доставка только через ссылку,
QR или ручной ввод.

## Второй администратор

Панель Remnawave допускает **только одного** администратора. При каждом
старте контейнера она оставляет самого старого и удаляет остальных
(`prisma/seed/seeders/12_verify-admin.ts`). Это не настройка, а поведение кода.

Поэтому доступ второму человеку выдаётся так:

1. **Users → Create user** — обычная учётка для работы с подписками;
2. **Settings → API Tokens** — отдельный токен, живёт в другой таблице
   и при перезапуске не удаляется.

Токен даёт полный доступ к API, обращайтесь с ним как с паролем.

## Пароли и секреты

| Что | Где |
|---|---|
| Пароль админа, API-токен, ключи REALITY, секрет ноды | `/opt/nsky/install-state.env` (права 600) |
| Пароль БД | `/opt/nsky/panel/.env` |
| Секрет ноды | `/opt/nsky/node/.env` |
| Лог установки | `/opt/nsky/install.log` |

Пароль администратора печатается в конце установки. Смените его при первом входе.

## Если что-то сломалось

```
cd /opt/nsky/panel && docker compose ps
```

```
docker logs --tail 50 remnawave
```

```
docker logs --tail 50 remnanode
```

Частые случаи:

- **Панель не открывается** — не выпустился сертификат. Проверьте, что домен
  указывает на IP сервера (`dig +short oijas.rknmrz.xyz`) и порт 80 открыт.
- **Нода не подключается** — не совпал `SECRET_KEY` или панель не видит ноду
  по `127.0.0.1:2222`. Смотрите `docker logs remnanode`.
- **Подписка пустая** — нет хостов или сквад не привязан к ноде.
  `--check` покажет оба параметра.
