# Стек на готовом решении (open source)

Дата: **5 ноября 2026**. Этот документ **заменяет** ранее предложенный вариант
«свой клиент на Flutter + свой control plane». Причина — ваши уточнения: открытый код
допустим, бумажная волокита не нужна, главное — чтобы работало и было понятно сотрудникам.

Короткий ответ: **всё уже написано**. Нужно развернуть три готовых компонента и настроить
шаблоны. Своего кода — ноль, или почти ноль.

---

## 1. Из чего состоит решение

```
┌── Сотрудник ──────────────────────────────────────────────┐
│  Приложение Happ / Hiddify / v2rayTun / Streisand          │
│  (ставят один раз, дальше — только кнопка «Подключить»)    │
└───────────────┬───────────────────────────────────────────┘
                │  подписка по HTTPS (ссылка в один тап)
┌───────────────▼───────────────────────────────────────────┐
│  Remnawave Panel   — админка + API + пользователи          │
│  Subscription page — страница «как поставить / подключить» │
│  Remnawave Node    — Xray-core, ноды, где живёт трафик     │
└───────────────────────────────────────────────────────────┘
```

| Компонент | Что делает | Лицензия | Готовность |
|---|---|---|---|
| **Remnawave Panel** `v3.4.8` | админка, пользователи, ноды, подписки, HWID-лимит устройств, Telegram-уведомления, REST API | AGPL-3.0 | зрелый, 3.x, активные релизы (последний 02.11.2026) |
| **Remnawave Node** `v3.4.4` | контейнер с Xray-core, к которому подключаются клиенты | AGPL-3.0 | зрелый |
| **Remnawave Subscription page** `v8.x` | страница для сотрудника: «скачай приложение → нажми кнопку», русский язык из коробки, deeplink `happ://add/...` — подписка добавляется в один тап | AGPL-3.0 | зрелый |
| **Xray-core** (внутри Node) | VLESS+REALITY, XHTTP, Hysteria2 | MPL-2.0 | ядро |
| **Happ / Hiddify / v2rayTun / Streisand** | клиенты для Windows/Android/iOS | разное (Happ — closed source, бесплатный) | готовые |

Что это даёт по вашим болячкам:

| Ваша проблема | Как решается здесь |
|---|---|
| «Клиенты не понимают, куда нажимать» | Страница подписки сама определяет ОС, даёт кнопку установки приложения и кнопку «Подключить» → приложение открывается с уже добавленной подпиской |
| «При смене конфигурации надо что-то менять» | Ничего менять не надо: приложение тянет подписку по расписанию. Поменяли сервер/протокол в панели — у всех обновилось |
| «Хочу управлять, а не писать» | Всё в веб-админке: пользователи, ноды, лимиты трафика/устройств, сроки |
| «Нужна админка на Android/Windows» | Панель — веб-приложение, ставится как PWA на телефон и на Windows. Отдельная программа не нужна |
| «Уведомления» | Встроенные Telegram-уведомления панели |
| «Не хочу бумажной волокиты» | AGPL при **использовании внутри компании** обязательств по раскрытию вашего кода не создаёт. Вы просто пользуетесь программой |

> Про AGPL: обязательство опубликовать исходники возникает, если вы **распространяете**
> программу или даёте к ней сетевой доступ **третьим лицам как сервис**. Внутреннее
> использование для своих сотрудников — обычная эксплуатация. Своих модификаций мы не
> планируем; если появятся — их надо будет открыть. Это единственное реальное ограничение,
> и оно не мешает работе.

## 2. Протоколы: что включаем на сервере

Ключевое, что изменилось с прошлого анализа: **Xray умеет Hysteria2 и как входящий протокол**
(`protocol: "hysteria"`, `version: 2`, список `users` с индивидуальным `auth`).
Проверено по документации Xray 05.11.2026. Это значит, что **отдельный `hysteria-server`
больше не нужен** — всё живёт в одном Xray на ноде.

| Приоритет | Инбаунд | Порт | Зачем |
|---|---|---|---|
| 1 | VLESS + REALITY (`xtls-rprx-vision`) | TCP 443 | основной, максимальная совместимость |
| 2 | VLESS + XHTTP (+REALITY) | TCP 443 | переживает «заморозку» длинных TLS-сессий (волна 17.02.2026) |
| 3 | Hysteria2 (в Xray) | UDP 443 | когда TCP режут или сеть плохая (мобильный интернет) |

Клиенту отдаём всё три в одной подписке — Happ/Hiddify умеют выбирать и переключать вручную
или автоматически.

Ограничения, которые надо знать (это не «нет», это «так устроено»):

- **Hysteria2 в панели — только для клиентов, которые умеют Xray-JSON подписку**
  (в подписи документации Remnawave прямо указано). Рабочие клиенты: **Happ, INCY**,
  частично Hiddify. Если выбранный клиент не умеет — он просто не увидит Hysteria2,
  останется REALITY. Проверить на пилоте.
- **На TCP/443 в Xray помещается один протокол.** XHTTP придётся повесить на другой порт
  (например 8443) — либо делать REALITY на 443, а XHTTP отдельным портом. Косметика,
  но об этом надо помнить.
- **REALITY и версии Xray.** Сервер Xray `v26.9.8+` требует от клиента
  `X25519MLKEM768` в ClientHello. Клиенты на Xray-core (Happ, v2rayNG свежие) — ок,
  sing-box-клиенты (часть Hiddify) — ломаются. Ещё одна причина, почему Happ основной,
  а Hiddify — запасной.

### Почему не «свой клиент» сразу

Свой клиент на Flutter — это 2–3 месяца работы (TUN на трёх платформах, kill switch,
автообновление, подпись Windows/iOS) и ровно те же грабли, на которых уже спотыкались.
Готовые клиенты эту работу уже сделали. Если через полгода пилота выяснится, что вам нужен
свой брендинг и свои экраны — вот тогда имеет смысл вернуться к своей обёртке, уже зная,
какой протокол и какая логика работают. Не наоборот.

## 3. Серверы: что заказывать

| Роль | Где | Минимум | Комментарий |
|---|---|---|---|
| **Панель** (Remnawave Panel + Postgres + Valkey + Subscription page) | РФ или любой хост, **не на IP ноды** | 2 CPU / 2–4 GB RAM / 20 GB | требования из официальной документации: мин. 2 GB, рекомендовано 4 GB |
| **Нода** (трафик сотрудников) | за рубежом: Финляндия / Германия / Нидерланды | 1 CPU / 1–2 GB / 20 GB | трафик гоняет Xray, ресурсы зависят от нагрузки |

Почему панель отдельно от ноды — важно: если IP ноды заблокируют или сервер ляжет,
панель останется доступной, и сотрудники получат новый конфиг. Если всё на одном хосте,
блокировка = нет VPN **и** нет управления.

Дополнительно:
- домен для панели (`panel.домен.ру`) и домен для подписки (`sub.домен.ру`) — TLS-сертификаты
  выпускаются автоматически (Caddy в официальном compose);
- **нода должна быть «чистой»**: не в подсетях, которые уже известны как VPN-хостинг —
  иначе часть сайтов будет капчить;
- для выхода за рубеж имеет смысл подать заявку в ЦМУ ССОП на включение IP ноды в «белый
  список» (см. `РЕШЕНИЯ.md` §2.1). Это снимет основную часть проблем с ТСПУ.

## 4. Установка: 3 шага (черновик, уточняется при развёртывании)

Всё ставится официальными средствами Remnawave. В репозитории лежат **заготовки** с
зафиксированными версиями — см. `deploy/`.

### Шаг 1. Панель

```bash
# на сервере панели (Ubuntu 22.04/24.04)
apt update && apt install -y curl
mkdir -p /opt/remnawave && cd /opt/remnawave
# compose и .env — из deploy/panel/
# заполнить .env: домены, пароли БД, APP_SECRET, TELEGRAM_BOT_TOKEN
docker compose up -d
```

Панель слушает только `127.0.0.1:3000` — наружу её отдаёт Caddy с TLS (официальный
`docker-compose-prod.yml` уже так устроен).

### Шаг 2. Нода

1. В панели: **Nodes → Create**, указать IP и порт `2222`.
2. Панель выдаст `SECRET_KEY` и compose-файл.
3. На сервере ноды: положить `deploy/node/docker-compose.yml`, подставить `SECRET_KEY`,
   `docker compose up -d`.

Нода ходит в панель по mTLS/секрету, наружу открыт только порт ноды и нужные инбаунды.

### Шаг 3. Профиль Xray (инбаунды)

В панели: **Config profiles → создать** и вставить один из шаблонов `deploy/xray/`:

- `profile-reality-xhttp-hysteria2.json` — три инбаунда, как в §2;
- либо взять готовый из каталога `remnawave/templates`
  (`Example VLESS-TCP-REALITY config`, `Example VLESS-SELFSTEAL-WITH-NGINX`).

Дальше: **Hosts** (какой хост/SNI отдавать клиентам), **Squads** (кто куда имеет доступ),
**Subscription settings** (что кладём в подписку).

## 5. Как это выглядит для сотрудника

**Первый раз (2 минуты, без инструкций):**

1. Админ создаёт пользователя в панели → получает ссылку на страницу подписки.
2. Отправляет её сотруднику в Telegram/почту (или одним сообщением из бота).
3. Сотрудник открывает ссылку → страница определяет его ОС → кнопка «Скачать приложение»
   → кнопка «Подключить» → приложение открывается с уже добавленной подпиской →
   разрешение VPN → готово.

**Каждый день:** открыл приложение → «Подключить». Всё.

**Когда что-то меняется на сервере:** ничего не делает. Подписка обновится сама
(приложение обновляет её при запуске и по таймеру).

**Если соединение не работает:** приложение показывает ошибку; в панели видно, кто
подключался и каким протоколом; можно переключить протокол в приложении (REALITY ↔ Hysteria2)
или выдать новый конфиг.

## 6. Что придётся сделать руками (реально)

Честный список работ, без «просто нажми кнопку»:

| # | Работа | Время |
|---|---|---|
| 1 | Заказать 2 сервера (панель + нода), домены, DNS | 1 вечер |
| 2 | Развернуть панель и ноду, выпустить сертификаты | 1–2 часа |
| 3 | Собрать профиль Xray (3 инбаунда), проверить с Windows/Android в Wi-Fi и LTE | 2–4 часа, и это главный риск |
| 4 | Настроить страницу подписки: брендинг, логотип, список приложений, русский текст | 1 час |
| 5 | Создать пользователей (импорт 50+ из таблицы/CSV) | 1 час |
| 6 | Настроить Telegram-уведомления панели | 30 мин |
| 7 | Прогнать пилот на 5–10 людях, зафиксировать проблемы | 1–2 дня |
| 8 | Резервное копирование панели (БД + .env) | 1 час |

Итого: **реально уложиться в 2–3 рабочих дня**, из которых критичный — пункт 3.

## 7. Где это не сработает «из коробки» (и что делать)

| Ситуация | Решение |
|---|---|
| Нужен **свой брендинг и один экран** для сотрудника | Сейчас: кастомная страница подписки (есть готовые форки) + `app-config.json`. Позже — своя обёртка |
| Нужно **биллинговать/продавать** | Есть готовые Telegram-боты-магазины (MIT/AGPL), но для внутреннего использования не нужно |
| Нужны **корпоративные ресурсы РФ** через тот же туннель | Отдельный инбаунд на ноде в РФ + правило маршрутизации в подписке; либо сплит-туннель в клиенте |
| Нужен **kill switch** на Windows | Есть в Happ/v2rayN настройками; проверить на пилоте, что именно вас устраивает |
| Нужен **свой админский APK** | Пока — PWA панели на телефон (иконка на рабочем столе). Если нужен APK/EXE — обертка PWA (Capacitor) или, позже, клиент к API панели |
| Нужно **автоподключение при старте Windows** | Настройка клиента (Happ/v2rayN) + автозапуск; проверить |
| Панель заблокируют по IP | Держите второй домен/IP для панели; или панель только по VPN/офисной сети |
