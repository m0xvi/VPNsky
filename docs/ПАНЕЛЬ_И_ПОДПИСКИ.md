# Панель Remnawave: пользователи и ссылки подписки

Практическая инструкция для администратора. Кто какую машину открывает —
см. [МАШИНЫ_И_КОМАНДЫ.md](МАШИНЫ_И_КОМАНДЫ.md): панель **работает на
нидерландском VPS (A)**, но **открывается в браузере на вашем ПК (D)**.

---

## 1. Вход

```
https://<домен>:8444
```

- Порт **8444**, не 443: на 443 висит только подписка.
- Доступ разрешён только с IP офиса (`ufw`). Из другой сети страница не
  откроется — это штатное ограничение, а не поломка.
- Логин и пароль: `ADMIN_USER` / `ADMIN_PASS` в
  `/opt/nsky/install-state.env` на машине A (права 600).
- **Смените пароль**: в Remnawave 3.4.x нет кнопки «сменить пароль» —
  официальный путь через Rescue CLI (`reset-superadmin` → повторная
  регистрация), см. раздел 6. После смены обновите `ADMIN_USER`/`ADMIN_PASS`
  в state через `nano`: иначе следующий запуск установщика не сможет войти.
- Второй администратор в Remnawave невозможен (сидер при каждом старте удаляет
  всех, кроме самого старого админа). Второму человеку дайте обычного
  пользователя + **Settings → API Tokens**; токен обращайте как пароль.

## 2. Навигация: что где

Левое меню панели [2](https://docs.rw/learn-en/quick-start/):

| Раздел | Что там | Когда трогать |
|---|---|---|
| **Overview → Home** | онлайн, трафик, статус нод | проверить, подключился ли сотрудник |
| **Management → Users** | сотрудники | **основная работа**: создать, выдать ссылку, отключить |
| **Management → Internal Squads** | сквад `Default-Squad` со ссылкой на инбаунды | новый инбаунд обязательно добавить сюда, иначе пользователи его не увидят |
| **Management → Config Profiles** | профиль Xray, 3 инбаунда: 8443/tcp, 2053/tcp, 443/udp | не редактировать руками — установщик обновляет по тегам |
| **Management → Hosts** | 6 записей: 3 прямых + 3 `(RU)` | отсюда берутся адреса в подписке; `(RU)` = адрес русского VPS |
| **Nodes** | нода `remnanode`, зелёная = подключена | красная → `docker logs remnanode` |
| **Tools** | HWID Inspector, SRH Inspector | разбор устройств и запросов подписки |
| **Subscription** | настройки страницы подписки | что видит сотрудник, открывший ссылку в браузере |

## 3. Создать пользователя (выдать доступ клиенту)

**Users → Create user** [1](https://docs.rw/learn-en/users/) [7](https://github.com/remnawave/panel/blob/main/docs/learn/quick-start.md):

1. **Username** — любое имя **без пробелов** (например `ivanov`). Это не ФИО, а
   идентификатор учётки в панели.
2. **Status** — `ACTIVE`.
3. **Traffic & Limits**:
   - *Data limit* — лимит трафика в ГБ (`0` = без лимита);
   - *Traffic reset strategy* — как часто сбрасывается счётчик
     (`NO_RESET`, `DAY`, `WEEK`, `MONTH`);
   - *HWID device limit* — лимит устройств, если поле есть в вашей версии
     (например 2: телефон + ноутбук; `0` = без лимита).
4. **Access Settings**:
   - срок действия подписки (`expireAt`);
   - **обязательно включите внутренний сквад `Default-Squad`**. Без него подписка
     будет пустой.
5. **Description** — заметка для себя (отдел, номер заявки).
6. **Create user**.

Сквад `Default-Squad` уже привязан ко всем инбаундам, поэтому новому пользователю
автоматически достанутся **все 6 хостов** — три прямых и три `(RU)`. Отдельных
«мобильных» подписок создавать не нужно.

## 4. Где взять ссылку подписки

После создания пользователя вы вернётесь в список Users
[1](https://docs.rw/learn-en/users/):

- **Иконка ссылки в строке пользователя** — копирует Subscription URL в буфер.
  Это основной способ.
- **Иконка карандаша** → *Edit user* — там эта же ссылка показана текстом.
- В *Edit user* есть кнопка **More actions** и меню **User Management Tools**:
  1. **Detailed Info** — VLESS UUID, Happ Crypto links;
  2. **Show usage** — статистика трафика;
  3. **HWIDs and Devices** — устройства, которые приходили с этим доступом
     (не все клиенты это передают);
  4. **Subscription QR Code** — QR-код ссылки, удобно для телефона;
  5. **Subscription links** — «сырые» строки `vless://`, `hysteria2://` и т.д.

Откройте ссылку в браузере: должна появиться **страница подписки** с кнопками
установки приложений. Это лучшая проверка, что всё настроено.

### Вид ссылки

```
https://<домен>/<SUB_SECRET>/api/sub/<shortUuid>
```

- `SUB_SECRET` — случайный **секретный сегмент**: он прячет известный сканерам
  путь `/api/sub` (сам `/api/sub` снаружи отдаёт 404).
- `shortUuid` — уникальный идентификатор конкретного сотрудника.
- Ссылка **одна на сотрудника**. Не публикуйте её в общих каналах, не кладите
  в репозиторий, не пересылайте в общий чат: любой, у кого есть ссылка,
  получит доступ.
- Передавайте через QR или личное сообщение. Для тестового пользователя ссылка
  также лежит в `SUB_URL` файла `/opt/nsky/install-state.env`.

### Что делать сотруднику

1. Happ / v2rayTun / Hiddify → «Добавить подписку» → вставить ссылку (или
   отсканировать QR со страницы подписки).
2. Появится 6 серверов. Для мобильной сети (Билайн) выбрать **вручную**
   `NSky REALITY (RU)`; автовыбор почти наверняка возьмёт прямой зарубежный.
3. Обновлять подписку лучше по Wi-Fi: сама ссылка ведёт на зарубежный домен,
   через релей идёт только `443/udp`. На LTE автообновление может не пройти —
   туннель при этом работает из кэша.
4. При смене протоколов/хостов на сервере **ссылку перевыдавать не надо** —
   клиент подтянет изменения сам.

> Наш клиент из `app/` (форк FlClash) ждёт Clash YAML, а панель по умолчанию
> отдаёт список `vless://`-строк. Для первого пилота берите готовые Happ /
> v2rayTun; чтобы подключить свой клиент, нужен шаблон **Templates** в формате
> Clash/Mihomo или конвертер.

## 5. Управление после выдачи

| Задача | Где |
|---|---|
| Временно отключить доступ | Users → статус `DISABLED` (или `Enable/Disable` в меню) [3](https://lobehub.com/mcp/your-username-remnawave-mcp) |
| Продлить срок / изменить лимит | карандаш → Edit user → Access Settings / Traffic & Limits |
| Посмотреть/освободить устройства | More actions → HWIDs and Devices |
| **Ссылка утекла** | отзыв/перегенерация подписки (*revoke subscription*) — старый URL перестаёт работать, настройки пользователя сохраняются [4](https://deepwiki.com/remnawave/python-sdk/4.2-encryption-and-security) |
| Уволился сотрудник | отключить или удалить пользователя |
| Добавили новый инбаунд | **Internal Squads → Default-Squad** → добавить инбаунд, иначе в подписку он не попадёт [6](https://docs.rw/learn/quick-start/) |

Если меняли хосты/протоколы вручную, попросите сотрудника нажать «Обновить
подписку» в приложении.

## 6. Что из присланного стоит переписать ⚠️

В переписке были показаны **инфраструктурные идентификаторы и один настоящий
секрет**. Разделяю их честно:

| Что было в выводе | Это секрет? | Что делать |
|---|---|---|
| **`SUB_SECRET=…`** (и тот же сегмент в `SUB_PUBLIC_DOMAIN=…`) | **Да, секрет** | **Переписать (ротировать)** — см. ниже. Это единственное, что реально нужно менять |
| Пароль администратора (светился в логе установки прошлой сессии) | **Да, секрет** | Сбросить через Rescue CLI (`reset-superadmin`), зарегистрировать нового админа и синхронизировать `ADMIN_PASS` в state |
| API-токен, приватный ключ REALITY, пароль БД | Да, секреты | В чат не попадали; лежат в state/`.env` с правами 600. Трогать не обязательно |
| Домен панели/подписки | Не секрет, но идентификатор | Не «переписать», а перестать публиковать. Уже убран из активных файлов репозитория |
| IP нидерландской ноды и русского релея | Не секрет, но идентификатор | То же: не публиковать дальше. IP при желании можно сменить только у хостера |
| Имена хостов VPS (`ams-…`, `msk-…`), строки `tcpdump` | Служебная информация | Риск минимальный; в чат больше не выкладывать |
| `www.microsoft.com` в SNI | Публичный домен-маскировка | Не секрет |

**Отдельно про публичный репозиторий:** в архивном
`docs/handoff/01_СОСТОЯНИЕ_VPS.md` и в `docs/ЗАМЕТКА_СЛЕДУЮЩЕМУ_АГЕНТУ.md`
остались упоминания домена/IP из прошлых сессий. Активные файлы
(`README.md`, `docs/СЕРВЕР_УСТАНОВКА.md`, скрипты) уже очищены. Архив оставлен
как история — скажите, если убрать и оттуда.

### Ротация `SUB_SECRET` (делать на машине A)

Последствие: **все уже выданные ссылки подписки перестанут работать**, придётся
скопировать их из панели заново — в том числе ссылку, уже отправленную на
тестовый телефон. Happ продолжит работать по кэшу, но **автообновление
подписки упадёт**, пока вы не замените ссылку. Поэтому ротацию лучше делать
после проверки Билайна (или сразу заменить ссылку в Happ).
Не используйте для этого `nsky-install.sh --wipe`: он удалит базу панели.

Сначала бэкапы:

```
cd /opt/nsky
cp install-state.env backups/install-state.before-rotation.env
cp panel/.env backups/panel-env.before-rotation.env
cp /etc/caddy/Caddyfile /etc/caddy/Caddyfile.before-rotation
```

Подготовить значения и убедиться, что исходные найдены:

```
OLD=$(grep -oP '(?<=handle /)[^/]+(?=/api/sub)' /etc/caddy/Caddyfile | head -1)
NEW=$(openssl rand -hex 6)
DOMAIN=$(awk -F= '/^DOMAIN=/{print $2;exit}' install-state.env)
SHORT=$(awk -F= '/^TEST_SHORT_UUID=/{print $2;exit}' install-state.env)
[[ -n "$OLD" && -n "$NEW" && -n "$DOMAIN" ]] && echo "можно менять" || echo "ОШИБКА: исходные значения не найдены"
```

Только если написало «можно менять»:

```
sed -i "s|/$OLD/api/sub|/$NEW/api/sub|g; s|strip_prefix /$OLD|strip_prefix /$NEW|g" /etc/caddy/Caddyfile
sed -i "s|^SUB_PUBLIC_DOMAIN=.*|SUB_PUBLIC_DOMAIN=$DOMAIN/$NEW/api/sub|" panel/.env
sed -i "s|^SUB_SECRET=.*|SUB_SECRET=$NEW|" install-state.env
sed -i "s|^SUB_URL=.*|SUB_URL=https://$DOMAIN/$NEW/api/sub/$SHORT|" install-state.env
caddy validate --config /etc/caddy/Caddyfile
systemctl restart caddy
```

Панель читает `SUB_PUBLIC_DOMAIN` при старте, поэтому контейнер надо
**пересоздать** (обычный `restart` новые переменные не подхватит):

```
cd /opt/nsky/panel
docker compose up -d --force-recreate --no-deps remnawave
```

Проверка (на машине A):

```
bash /root/nsky-cascade-check.sh
```

Ожидаемо: `✓ Caddy и панель используют один секретный сегмент`,
`✓ SUB_SECRET в state совпадает с Caddyfile`, `✓ публичная ссылка отвечает
(HTTP 200)`. После этого **заново скопируйте ссылки у всех пользователей**
(Users → иконка ссылки) — `shortUuid` у каждого останется прежним, изменится
только секретный сегмент.

### Смена пароля администратора

В Remnawave 3.4.x **нет** ни кнопки «сменить пароль», ни API-эндпоинта для
этого: в исходниках есть только `auth/login`, `auth/register`, passkey и
OAuth2. Официально документированный способ — **Rescue CLI**, который удаляет
супер-админа, после чего панель снова показывает форму регистрации
[2](https://docs.rw/learn-en/quick-start/).

Делать на **машине A**. Это не `--wipe`: база, пользователи, хосты и нода
остаются на месте; удаляется только учётка администратора.

```
docker exec -it remnawave cli
```

В меню стрелками выберите **Reset superadmin** → подтвердите `Yes`. Должно
появиться `Superadmin ... was reset successfully. Please open the login page
and set a new one.` Затем:

1. Откройте `https://<домен>:8444` — появится форма регистрации. Задайте
   **новые** логин и пароль (пароль: 24+ символа, верхний/нижний регистр и
   цифры — такие требования панели).
2. На машине A: `nano /opt/nsky/install-state.env` → исправьте `ADMIN_PASS`,
   а если меняли логин — и `ADMIN_USER`. Не вставляйте пароль в командную
   строку: он останется в истории bash.
3. Проверьте вход в панель. API-токен лежит в отдельной таблице и обычно
   переживает сброс; если `bash nsky-cascade-check.sh` начнёт ругаться на токен —
   создайте новый в **Settings → API Tokens** и обновите `API_TOKEN` в state.

> Перед сбросом сделайте бэкап: `cp /opt/nsky/install-state.env
> /opt/nsky/backups/install-state.before-admin-reset.env`. Не делайте это
> одновременно с проверкой Билайна — меньше переменных в диагностике.
