# Какая команда — на какой машине

Шпаргалка, чтобы не путать окна PuTTY. Всего **четыре точки**, и серверных
команд касаются только первые две.

| | Машина | Как узнать | Что там живёт |
|---|---|---|---|
| **A** | **Нидерландский VPS (панель)** | промпт вида `ams-…`, есть `/opt/nsky/install-state.env` | Remnawave, Postgres/Valkey, Caddy, Xray-нода, подписка |
| **B** | **Российский VPS (релей)** | промпт вида `msk-…`, есть `/opt/nsky-relay/` и правила DNAT | только iptables + systemd, **панели нет** |
| **C** | **Телефон сотрудника** | Билайн, мобильный интернет | Happ / v2rayTun / Hiddify |
| **D** | **Ваш ПК в офисе** | браузер и PuTTY | доступ к панели и к A/B по SSH |

> Панель **работает на A**, но **открывается в браузере на D** (`https://<домен>:8444`,
> только с IP офиса). На D никаких серверных команд не запускаем.

---

## A — нидерландский VPS (панель)

Здесь запускается **обычный режим** чекера (без флагов) и всё, что относится к
панели, Caddy и состоянию установки.

```
cd /root
curl -fsSL -o nsky-cascade-check.sh https://raw.githubusercontent.com/m0xvi/VPNsky/2ad3e4b8007b8ee6a3aa3efe2d5ba29d34a64fc2/deploy/nsky-cascade-check.sh
bash nsky-cascade-check.sh
```

Ещё на A:

```
grep '^SUB_SECRET=' /opt/nsky/install-state.env
bash /root/nsky-install.sh <домен> <email> --check
docker logs --tail 30 remnanode
ufw status
```

Фикс/ротация `SUB_SECRET`, правки `/etc/caddy/Caddyfile`, `/opt/nsky/panel/.env`,
`/opt/nsky/install-state.env`, рестарт Caddy и панели — **только на A**
(см. [ПАНЕЛЬ_И_ПОДПИСКИ.md](ПАНЕЛЬ_И_ПОДПИСКИ.md), раздел «Что переписать»).

**НЕ запускать на A:** `nsky-cascade-check.sh --relay`, `nsky-relay.sh`,
любые команды из раздела B. Признак ошибки: «Не знаю IP нидерландской ноды».
`nsky-install.sh` запускать без `--wipe`, только при реальной необходимости.

---

## B — российский VPS (релей)

Здесь запускается **только режим `--relay`**. Файла
`/opt/nsky/install-state.env` на этой машине нет и быть не должно.

Одной строкой (скачать + сразу проверить, чтобы вставка не склеилась):

```
curl -fsSL -o /root/nsky-cascade-check.sh https://raw.githubusercontent.com/m0xvi/VPNsky/2ad3e4b8007b8ee6a3aa3efe2d5ba29d34a64fc2/deploy/nsky-cascade-check.sh && bash /root/nsky-cascade-check.sh --relay
```

Ещё на B:

```
bash /root/nsky-relay.sh --status
iptables -t nat -L PREROUTING -nv
systemctl status nsky-relay.service
```

**НЕ запускать на B:** `nsky-cascade-check.sh` без `--relay`,
`nsky-install.sh`, `docker …`, `grep … /opt/nsky/install-state.env`.
Признак ошибки: «`/opt/nsky/install-state.env` не найден» — значит, вы запустили
режим A не на той машине.

## C — телефон (Билайн, LTE, без Wi-Fi)

Никаких команд. Только действия в приложении:

1. По Wi-Fi добавить ссылку подписки, обновить её.
2. **Вручную выбрать сервер `NSky REALITY (RU)`** (не прямой).
3. Выключить Wi-Fi, включить мобильные данные.
4. Подключиться → проверить внешний IP (`2ip.ru` / `ipinfo.io`).
5. Если не пошло — по очереди `XHTTP (RU)`, `Hysteria2 (RU)`.

Подробности: [ПРОВЕРКА_КАСКАДА.md](ПРОВЕРКА_КАСКАДА.md), раздел 4.

---

## D — ваш ПК

- Браузер → панель `https://<домен>:8444` (только с IP офиса; из другой сети
  страница не откроется — это не поломка).
- PuTTY → отдельное окно на A и отдельное окно на B.
- GitHub → скачивание скриптов / чтение документации.

---

## Быстрая расшифровка ошибок «не на той машине»

| Сообщение | Что произошло | Что сделать |
|---|---|---|
| `/opt/nsky/install-state.env не найден` | Обычный режим запущен на **B** | Закрыть, перейти на **A** или добавить `--relay` |
| `Не знаю IP нидерландской ноды. Укажите --nl` | `--relay` запущен на **A** | Перейти на **B** |
| `bash: nsky-cascade-checurl …` | Склеилась вставка в PuTTY | `Ctrl+C`, вставлять **по одной строке** |
| Панель не открывается в браузере | Вы не с IP офиса | Разрешить IP в ufw на **A** (см. [ПРОВЕРКА_КАСКАДА.md](ПРОВЕРКА_КАСКАДА.md), раздел 5) |

**Правило:** одно окно PuTTY = одна машина. Прежде чем нажать Enter, смотрите на
промпт: `ams-…` → раздел A, `msk-…` → раздел B.
