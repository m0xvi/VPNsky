## 2. Практические обязательства

### 2.1. MPL-2.0 (Xray-core)

- Если вы **не меняете** файлы Xray — обязательств почти нет, кроме сохранения уведомлений.
- Если меняете (например, патчите TUN под Windows) — изменённые файлы должны быть доступны
  под MPL-2.0. Достаточно выложить патчи/форк, закрытый код вокруг остаётся закрытым.
- MPL **не требует** открывать ваш Dart/Flutter-код.
- Практика: держите патчи отдельным небольшим форком с публичной ссылкой в notices.

### 2.2. MIT (Hysteria2, libXray, AmneziaWG, hev)

Минимально: файл `THIRD_PARTY_NOTICES` в установщике и в приложении («О программе»),
с copyright и полным текстом лицензий.

### 2.3. wintun

`wintun.dll` нельзя модифицировать и нельзя «переупаковывать» отдельно от продукта.
Распространяется рядом с вашим приложением, которое использует его через `wintun.h`.
Требуется уведомление о правах WireGuard LLC. Практическая мелочь, но она попадает в
инсталлятор и в SBOM.

### 2.4. Подпись и распространение в Windows

- До production нужен **Authenticode**-сертификат (иначе SmartScreen блокирует установку у
  сотрудников). Ключ — в защищённом хранилище/HSM, не в GitHub Secrets в открытом виде.
- Сборка должна быть воспроизводимой настолько, насколько это возможно; артефакт —
  из одного job, а не пересобранный отдельно для релиза.

### 2.5. Android

- Отдельный release keystore, не в репозитории; backup в защищённом месте — потеря ключа
  делает невозможным обновление приложения поверх установленного.
- Test и production ключи — разные.

## 3. Apple: что действительно требуется

| Утверждение из архива | Факт (проверено 05.11.2026) |
|---|---|
| «Лицензия не нужна» | Лицензия на **ПО** — да, Xray/libXray MIT/MPL. Но **Network Extension entitlement** выдаётся только участникам платной Apple Developer Program (~$99/год). Бесплатный аккаунт не даёт VPN-возможностей. |
| «Ставим самостоятельно через кабель на каждое устройство» | Технически возможно (Xcode + dev-профиль), но профиль ограничен по времени; для 50+ устройств это нерабочая эксплуатация. |
| Публичный App Store | Правило 5.4: VPN-приложения — только от организаций, с проверкой приватности. Для внутреннего использования — Apple Business Manager + Custom Apps / MDM, либо TestFlight. |

**Что сделать до iOS-этапа:** оформить Apple Developer Program (организацию, не личный
аккаунт — для App Store 5.4 нужен D-U-N-S), решить способ доставки (MDM/TestFlight),
и только потом начинать код. Проверить актуальные условия перед оплатой.

## 4. Правовая рамка в РФ (не юридическая консультация)

Проверенные факты по публикациям на 2026 год:

- Использование VPN само по себе не запрещено; ответственности за «включённый VPN» нет.
- Ст. 13.52 КоАП — для **владельцев** VPN-сервисов, уклоняющихся от взаимодействия с РКН
  (штрафы до 500 тыс. ₽, повторно до 1 млн ₽).
- Ст. 13.53 КоАП — за умышленный поиск экстремистских материалов (3–5 тыс. ₽); VPN упоминается
  как способ, а не как состав.
- Реклама/популяризация средств обхода блокировок — отдельные штрафы (для организаций
  существенные). Это касается **публичных** материалов, не внутреннего корпоративного канала.
- Роскомнадзор в апреле 2026 публично заявил, что использование VPN для корпоративного
  взаимодействия внутри страны не ограничивается; для доступа к зарубежным ресурсам
  предусмотрен порядок заявления и включения адресов в «белый список».

Что из этого следует для проекта:
1. Не делать продукт «публичным VPN-сервисом» — это включает ст. 13.52 и требования к
   подключению к ФГИС. Корпоративный внутренний контур — другой режим.
2. Не публиковать инструкции «как обойти блокировки» в открытых каналах — только внутренняя
   документация для сотрудников.
3. Если сервер предназначен для выхода за рубеж — рассмотреть официальный порядок
   (заявление в РКН, «белый список» IP). Это снимет часть рисков и, возможно, часть проблем
   с ТСПУ.
4. Перед запуском — консультация юриста именно по вашей организационно-правовой форме и
   географии серверов.

## 5. Что положить в репозиторий в итоге

```
LICENSE                 # ваш проприетарный текст
THIRD_PARTY_NOTICES     # MIT/MPL/GPL-wintun тексты + copyright
docs/licenses/          # копии лицензий компонентов, версия и commit
patches/xray/           # ваши патчи к MPL-компонентам (публикуются)
sbom/                   # SBOM (CycloneDX), генерируется в CI
```

Важно: **не** кладите в репозиторий архив из `docs/handoff/` целиком при публикации
чего-либо — в нём IP, домен и внутренняя топология VPS.

## 6. Риски, которые нужно закрыть до релиза

| Риск | Действие |
|---|---|
| Забыли notices → формальное нарушение MIT | Чек-лист в релизном workflow |
| Патчи к Xray не опубликованы → нарушение MPL | Публичный форк/патчи в том же релизе |
| Использован GPL-код из чужого клиента (скопировали кусок UI/логики) | Явный запрет копировать код из Hiddify/Karing/v2rayN; только свои реализации или MIT/MPL-источники |
| Тестовый keystore утёк | Ключи только в защищённом хранилище, ротация при инциденте |
| iOS-сборка без платного аккаунта | Оформить Apple Developer Program заранее |
| Требование App Store 5.4 | Организационный аккаунт + политика приватности |
