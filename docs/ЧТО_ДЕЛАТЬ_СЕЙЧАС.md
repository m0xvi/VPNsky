## Что показал ваш tcpdump (и что я понял неверно в прошлый раз)

ВCaptured пакетах есть `Flags [.], seq 0:1024, length 1024` — это **настоящий
TLS ClientHello с телефона, который дошёл до NL-ноды**. SYN, ACK и данные
прошли через русский релей. Значит:

- DPI Билайна **не обрывает** соединение на подлёте (мой прошлый вывод был
  ошибочным);
- DNAT, FORWARD, MASQUERADE и сам каскад RU → NL **работают полностью**;
- проблема осталась в одном месте: **Xray/REALITY на NL-ноде не отдаёт ответ
  клиенту** (или ответ не доходит обратно).

Важная оговорка: ваш фильтр `src host <RU>` ловил **только входящие** пакеты.
Отсутствие ответов в том выводе поэтому **не доказательство** — ответные пакеты в
него просто не попадали. Нужен замер в обе стороны, он и даст точный ответ.

Три наиболее вероятные причины, все на NL-ноде:

1. разошлись ключи REALITY (`pbk`/`shortId`) между подпиской и конфигом Xray —
   после пересоздания контейнера панели и смены секрета это реально;
2. REALITY не может дотянуться до `target www.microsoft.com:443` и молчит;
3. ServerHello с сертификатом больше MSS 1360 и режется по MTU на LTE.

## Одно действие — нидерландский VPS (`ams-…`)

Вставить **одной строкой**, Enter. Скрипт только читает, ничего не меняет:

```
curl -fsSL -o /root/nsky-live-probe.sh https://raw.githubusercontent.com/m0xvi/VPNsky/12d5de13e0919a69be5578e5bab790c5d7df72e2/deploy/nsky-live-probe.sh && bash /root/nsky-live-probe.sh
```

Когда скрипт напишет «СЕЙЧАС нажмите «Подключить»», на телефоне:

1. Happ → **Отключить** (если держит «ПОДКЛЮЧЕН»).
2. Сразу нажать **«Подключить»** с выбранным `NSky REALITY (RU)`.
3. Подождать 15 секунд, пока скрипт дослушает.

Скрипт сам:
- сверит ключи REALITY из подписки и state, **не печатая их**;
- посчитает пакеты **в обе стороны** и пакеты с данными;
- покажет ошибки Xray из лога ноды;
- выдаст один вердикт: `A` / `B1` / `B` / `C`.
