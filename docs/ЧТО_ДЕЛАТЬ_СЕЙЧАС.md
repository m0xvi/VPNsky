## Важно: прошлый вывод скрипта был ошибочным

Скрипт v`.1` напечатал `✗ РАСХОЖДЕНИЕ shortId` и посоветовал перезапустить
установщик. **Не делайте этого** — установщик перегенерирует все ключи и убьёт
все выданные ссылки, а проблема была в самом скрипте. Три бага:

| Что напечаталось | Почему это было неверно |
|---|---|
| `✗ РАСХОЖДЕНИЕ shortId` | Парсер брал `sid` вместе с `#NSky%20REALITY%20(RU)` из конца ссылки. `pbk` шёл раньше и распознался верно — поэтому он и показал `✓`. |
| Сравнение с `state` | Нода работает **не по файлу state**, а по живому конфиг-профилю в панели. Расхождение со state ничего не доказывает. |
| `Вердикт B1: 0 пакетов с данными` | `24 + 16 = 40` — ровно лимит `-c 40`. Захват обрезался на лимите; ответные пакеты просто не попали в выборку. |
| `✓ в последних 80 строках ошибок нет` | `grep: binary file matches` — лог бинарный, `grep` отказался его читать. Ошибки Xray не были показаны. |

Всё исправлено в v`.2`: `#remark` отрезается, `sid` сверяется **с живым
профилем панели** (`/api/config-profiles`), лимит `-c` убран, логи читаются
бинарно-безопасно, добавлена проверка доступности `target REALITY` с NL-ноды.

## Что по-прежнему доказано

- `length 1024` в вашем tcpdump — настоящий **TLS ClientHello с телефона дошёл
  до NL-ноды**. DNAT, FORWARD, MASQUERADE и весь каскад RU → NL работают.
- DPI Билайна на подлёте ни при чём, `tcp/443` на релее добавлять не надо.
- Две одинаковые строки `tcp dpt:443` — безвредный дубликат.
- Осталась одна область: **Xray/REALITY на NL-ноде** — ключи профиля,
  доступность `target` или ответные пакеты.


Когда напишет «СЕЙЧАС нажмите «Подключить»»: в Happ **Отключить** → сразу
**Подключить** с `NSky REALITY (RU)` → подождать 15 секунд.

Скрипт сверит `shortId`/`privateKey` с живым профилем, посчитает пакеты в обе
стороны без обрезки, покажет реальные ошибки Xray и проверит, доступен ли
`target REALITY` с ноды. Значения ключей не печатаются.
